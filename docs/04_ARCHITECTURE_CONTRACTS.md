# DNDTurn：更正后的目标架构合同

版本：**2026-09-26 / 073919 架构基线**。

**性质：后续重构的技术目标，不是当前已实现 API，不是新增玩家规则。**本文的描述性类型/组件名称是职责示例，不要求照名称增加一批空壳类；是否落实由01的源码事实和02的G项验收决定。03中已经确定的场地、费用、退出、同意、时钟和范围政策不因本文件改变。

## 0. 保留的基础与本次不做的事

保留单一CombatEngine、纯Java17 common、有类型意图、有限执行许可、原版移动/碰撞/受伤链、世代与结果去重、模拟和表现隔离。不要为了重构建立第二套成员/资源权威、第二个角色移动循环、全局AI替代框架或Minecraft世界回滚系统。

本次不设计新的AP、多职业技能规则、完整PvP、Boss/飞行专属玩法，也不把原版Brain/Goal天然视为纯决策系统。不要求所有问题一次完成；从稳定合同逐条迁移，并用不同适配验证扩展成本。

## 1. 职责、状态所有者与依赖方向

```text
玩家输入 / Mob决策适配
          ↓
显式选择命令 + 无副作用的能力发现
          ↓
规范行动意图（执行者、能力、来源、目标、已确认选择）
          ↓
规则裁决和有限授权 ─────────── CombatEngine（唯一规则事实）
          ↓
执行计划/租约 ─────────────── 平台执行协调（真实世界）
          ↓
观察到的效果 + 资源提交 + 单一终态
          ↓
存档检查点 / 只读投影 / 演出事件
          ↓
客户端控制状态 / 显示适配
```

| 状态 | 唯一写入职责 | 其他模块的访问方式 |
|---|---|---|
| 会话、成员、先攻、阶段、资源、操作终态 | CombatEngine | 命令/不可变值快照，不直接改集合 |
| 原版实体、方块、物品和世界效果 | Minecraft平台执行链 | 有作用域的适配器在正确线程执行 |
| 移动/使用/效果Lease | 执行协调器及具体执行驱动 | 显式获得、验证、释放，不看“是否有operationID”猜权限 |
| 几何域、别名、held tick所有权 | 对应域/调度所有者 | 带修订号的查询及明确迁移步骤 |
| 当前退出暂停豁免 | 独立实时授权记录 | 根据03规则生成/撤销，不从历史回执重新推导 |
| 历史回执、因果和恢复检查点 | 历史/持久化职责 | 只读查询、引用保持与恢复审计 |
| 客户端已确认事实 | 有序投影 reducer | 只读；不是再维护另一套规则 |
| 尚未提交的选择、菜单、相机 | 客户端交互/CameraRig | 不改变服务器费用、身份和世界 |
| 动画时钟/事件片段 | 表现运行时与通道适配器 | 只写授权显示字段，不修改模拟事实 |

从ServerCombatService提取职责时先标清创建、推进、取消、卸载、合并、恢复和销毁谁负责。调用多一个facade但状态和控制权未改变，不构成抽象改善。平台事件适配只负责翻译固定版本入口、线程/上下文及调用狭窄接口，不把业务判断复制到多组Mixin。

关联：G15/G31/G40/G43；证据E05–E07。

## 2. 身份、版本与时间不是一个通用数字

### 2.1 身份合同

区分稳定实体UUID与当前实体实例、连接身份与当前连接实例、会话逻辑ID与合并别名、服务器世代与会话序号、operationID与执行许可、选择revision与规则version、结果游标与展示事件sequence。

同ID同负载返回既有结果；同ID不同规范负载冲突。恢复/连接/实例切换使旧许可失效，但不能删除仍有效的历史因果。合并canonical ID只解决名称归一，不自动迁移所有资源或安全范围。

内部可以用有意义的值类型阻止把选择revision传到结果游标位置，但不要凭空新增互相竞争的全局时钟。每种版本只回答一个问题。计划内部使用当前权威版本推进，不能把自身移动导致的版本变化当成外部过期，也不能因此取消所有复验。

### 2.2 时间合同

| 时间类别 | 合法用途 | 禁止的混用 |
|---|---|---|
| 世界日程/gameTime | 昼夜和明确保留的世界时间语义 | 不把它自动当作暂停后仍应冻结的行为期限 |
| 获准模拟步 | 移动、环境及对应实体子系统 | 不在渲染/为了补帧时重复跑身体tick |
| 行动执行进度 | 拉弓、食饮、技能准备与持续执行 | 不用装饰动画结束决定命中/耗物 |
| AI记忆/冷却策略时间 | 由适配器声明冻结、继续或重新基准 | 不假定Goal倒数和Brain绝对截止自然一致 |
| 持久累计服务器tick | 既定七日归档/非投射物操作截止 | 不受gameTime快进缩短，不变成箭寿命 |
| 确认窗口/实际服务器tick | 同意400tick、反应100tick等既定政策 | 不用FPS/系统墙钟随意改变窗口 |
| 客户端装饰时间 | 待机、姿态过渡和允许的纯视觉发射 | 不推进真实实体状态/物品/效果期限 |

`.109` Brain行为存在以gameTime构造绝对截止的路径；只拦截tick不足以证明所有AI时间冻结。需要逐适配声明，不修改全局gameTime冒充局部时钟。[证据E15](reviews/20260926-073919-source-evidence.md#e15)

关联：G18/G47及G45。

## 3. 授权对象与历史证据分开

一次根请求身份不是执行权限。许可至少关联当前世代、执行者、操作/阶段、能力、受限目标/作用范围、预算、使用次数及失效条件；每个真实入口重新核对其仍有效。运行的Java对象或ThreadLocal只是短生命周期执行桥，不能跨tick、排队任务、网络或恢复被默认继承。

历史退出回执证明“这个退出请求已经处理过”；实时豁免证明“该玩家目前允许不被该场地暂停”。二者应各自有记录和撤销合同。实时豁免可引用退出operationID作为来源，但不能扫描任意旧回执决定授权；重新加入、生命周期离场、会话关闭/合并后按既定规则对账。归档旧回执不得使当前正常玩家突然冻结，旧回执也不能在后来离场时复活已撤销豁免。

外来效果另区分历史来源域、当前模拟域、当前目标域。三者同域也不替代具体授权，三者不同也不能先删合法效果再错过因果合并机会。未知箭隔离是明确的特殊安全状态，不等于仍持有可造成新效果的许可。

关联：G02/G03/G19/G40；当前耦合见[E05](reviews/20260926-073919-source-evidence.md#e05)。

## 4. 命令、纯发现与计划执行

### 4.1 选择装备是显式命令

当前discover中会设置选槽并同步库存，这是经校验的“选槽并查询”组合，不是已证实未授权漏洞；但不能把它当作无副作用查询复用于AI评分、悬停和预览。

目标流程：

```text
SelectEquipment（意图与版本、按现有免费整理规则）
  → 校验并确认SelectionSnapshot
DiscoverAbilities（读取已确认选择和目标快照）
  → 返回有界选项、不可用ReasonCode、预览依赖
SubmitAction（规范能力+来源+目标+选择证据）
  → 规则校验/必要资源预留 → 计划
```

传输可保留一个显式的组合用户命令以减少往返，但服务端组合内部必须区分命令和纯查询，AI/hover只能调用后者；取消预览不会暗中回滚已合法确认的装备切换。数字键和UI共用这条语义，不靠延迟一tick修时序。

发现不扣动作、不移动、不调用可能产生副作用的Goal/物品执行函数。预览结果只是提案，不能作为无限期许可；提交时重新验证身份、物品和作用条件。

### 4.2 三种“计划”不混用

- 回合策略决定下一次做什么；可以在一次合法行动结束后用剩余预算再决策。
- 行动计划完成一次已选行为：准备、必要时接近、复验、执行、观察、终态。
- 路径只给出到合法执行位置的空间提案；边权不决定移动费。

暂不需要把当前一次接近+一次能力的PLAN改为通用工作流引擎。更不应让每个攻击执行器都自动结束回合。AI主动换目标必须产生明确的新决策/中断，而不是导航观察中偷偷替换。

关联：G21/G35/G37；证据E02/E10/E13。

## 5. 结果、取消、清理与费用提交

### 5.1 一次计划至少有三类结论

| 内容 | 示例 | 意义 |
|---|---|---|
| 世界执行事实 | 攻击尝试已开始、生命损失已观察、方块放置未被处理 | 世界到底已知发生了什么 |
| 资源提交事实 | 动作已消费、移动3tick、物品消耗1 | 费用是否已经提交，不由UI或清理成功推断 |
| 控制释放结果 | 导航已停、使用状态已释放、释放异常需隔离 | 后续是否安全继续，不改写过去已确认的效果 |

单一根operation仍只有一个规范终态；增加分量是为了正确聚合，而不是允许多个模块各自发布相反终态。完成、取消请求、中断原因和最终release是不同职责。至少使release幂等，成功完成也能安全释放，而无需调用语义含糊的cancel模拟“收尾”。

如果世界副作用仍未知，应保留UNKNOWN；如果世界已明确成功但清理失败，应保留已确认效果/费用并记录控制故障，按风险隔离或停止后续调度。不能统一把UNKNOWN改成功，也不能把成功效果抹成“没发生”。清理故障后的根终态映射应在规则/协议中明确并测试，不能由不同catch分支各自决定。

### 5.2 费用遵循03，不由重构重定

注册/查询/预览/接近不提前收攻击动作。实际合法攻击开始收动作，未命中不退。放置/使用按已确认的原版接受边界，破坏/持续使用按一次根行为计费。已发生移动独立保留，不按包/tick重复扣普通动作。取消不可回滚已经产生的世界效果，未知结果不可再次执行碰运气。

资源预留如采用，须由唯一规则权威可见，并与最终提交/撤销区分；不得额外引入玩家AP或临时减一再悄悄加一的第二套余额。

### 5.3 父子结果与观察

每个效果有稳定来源（根operation、步骤/效果序号、执行者和目标），父计划汇总从已确认子结果派生，不能把父子damage/费用相加两次。历史结果不可就地修改；新的恢复判定以追加对账结果/明确协议表示，不伪造原始终态。

关联：G04/G07/G39/G41；具体混用见[E04](reviews/20260926-073919-source-evidence.md#e04)。

## 6. 世界适配合同：依赖、许可、执行、观察

### 6.1 每类能力提供有限而可核验的边界

规范能力描述应将能力ID/版本、来源（物品/天然/状态授予）、目标合同、规则费用分类、执行驱动和效果类别分开。当前Capability enum的目标约束/ItemReference/Operation.Kind映射不应成为所有未来技能的唯一扩展点。

| 合同 | 应提供的内容 |
|---|---|
| 读取依赖 | 决策/预览依赖了哪份物品、目标身份/实例、方块/必要BE或菜单状态、能力状态和移动体型 |
| 实际作用范围 | 直接放置/破坏/移动/状态/生成位置和受影响实体；不得仅点击格 |
| 执行入口 | 在正确线程通过原版或明确适配的函数推进；允许哪些子系统，拒绝哪些回退 |
| 观察结果 | 伤害、物品数量/耐久、方块变化、生成身份、状态施加等有类型值，以及确定性等级 |
| 中断与恢复 | 开始前、接受后、效果已发生、清理期分别如何结束；什么可以重建，什么绝不重放 |

只捕获本次行为必要的有界依赖，不哈希整片世界来装作事务。物品序列化指纹是内容证据，不是天然的物品实例/代次证明；槽位/容器、选择版本与内容应按行为语义组合。位置、脚底、包围盒中心、方块中心和命中面各有用途，不把GridCell当成所有位置的单位。

### 6.2 不虚构原子回滚或全面保护

当前精确物品/方块类型白名单与TacticalImpact的直接多格范围是合理的保守实现。未知override、特殊BE组件、生成/流体等新效果没有完整契约前应显式unsupported，不宽泛匹配父类放行。

免费USE_BLOCK只调用方块自身分支，不能回退UseItemOn或手持物品；开箱成功不授权任意菜单存取。模组只提供事后placement事件时，不能宣称在首个写入前已经获得其保护许可。

邻居传播、计划更新和即时红石等须按已有支持范围独立分类；不能因为获得直接写入权限就把所有连锁效果当作免费附带许可。不能安全控制的能力须拒绝或明确不在支持范围，不能先副作用后setBlock回滚冒充事务。

关联：G11/G12/G14/G34/G41；证据E04/E08。

## 7. 扩展接口：执行能力与表现能力两条轴

### 7.1 服务端扩展

执行者合同提供被允许的能力：玩家背包/手别、Mob导航、天生攻击、目标根实体/部位映射等。玩家输入只是一种意图来源，AI不伪造玩家或发网络包；两者共用规则校验与计划后端。

策略读取已审计感知、定向关系、可用能力和资源，提出行为，不在评分时改世界。保留原版可安全复用的状态/执行路径；不能让Goal/Brain跑一遍再假装只读取其意图。当前非敌对地面路径/漫步是用户已批准的有限策略，不用它推断所有生物的攻击、工作、繁殖与特殊技能。

“可加入、可暂停、可被攻击、可移动、可自主决策、可执行某技能”分别报告支持程度。未知Mob不能一边加入先攻、一边静默当成Zombie或完全任意行动。外部根生物与PartEntity命中部位由适配器映射，不为每个部件默认创建一份回合资源。

### 7.2 客户端扩展

核心只提供身份、事实、时间源、事件去重和状态生命周期；适配器持有自己的动画状态并声明通道（待机、步态、攻击片段、使用、受击、特殊骨骼、视觉发射器）与字段所有权。不要继续向核心Pose塞Frog/Warden/每个mod的字段。

内置Player/Zombie/Bat/掉落物也应成为注册系统的使用者。未知renderer保留默认字段，注册后才能接管相应通道。客户端显示适配是否安装，不决定服务器攻击权限。

### 7.3 注册与兼容合同

注册内容包括稳定ID、行为版本、匹配范围、平台/线程、字段或执行通道所有权、依赖和恢复支持。明确启动注册/冻结时点，若允许资源重载则为旧计划保留对应版本或按明确中断合同处理；不让现有计划执行到一半换掉适配器。

重复ID拒绝、多个匹配的优先级/冲突诊断、缺失适配的unsupported原因、客户端未知显示扩展的降级与服务器未知行为的拒绝分别规定。64个注册上限是当前工程保护，不是对未来mod规模的玩法承诺。

同一JVM中的其他mod并不是隔离的不可信脚本沙箱。上述许可保证针对已审计接入链，不能宣称能够阻止任意mod直接修改世界或绕过自己的回调；超出覆盖的入口必须明确兼容限制。

兼容验收的关键：独立测试compat模块只注册自己的适配，不改ClientPresentation/ServerCombatService/通用Mixin就完成一种新执行者的行为与表现闭环。先以相差明显的两种测试实体证明接口，不先制造一个巨大的MobAdapter。

关联：G21/G34/G46；证据E02/E10/E11/E15。

## 8. 持久化、合并与长期历史

### 8.1 四种数据载体分离

| 载体 | 信任与寿命 | 不该装什么 |
|---|---|---|
| Wire DTO | 不可信输入/有界输出；协议版本 | 客户端自报最终成本、可信伤害、任意Java类型 |
| 规范行动意图 | 服务端校验后的纯值；operation去重 | LiveEntity/Navigation/线程上下文 |
| 执行上下文 | 当前世代、线程和实例的短/跨tick许可状态 | 直接反序列化恢复的旧对象引用 |
| 持久检查点/证据 | 可迁移、可审计的值及必要引用 | 声称等同区块/实体/世界副作用的原子快照 |

保持协议17/common5/envelope6是三个独立轴。后续变更明确谁迁移谁、拒绝什么，不要求每次一起自增。规范化负载与行为版本共同参与去重；注册器变更、关键配置和恢复证据需要可核验，不依赖“同名类还在”。

### 8.2 检查点不是世界事务

SavedData.setDirty只标记待保存；当前persistNow只更新SavedData状态。即使会话JSON写入完成，也不等于相关实体、区块、物品和held tick同时持久化。保留恢复先校验候选、再安装、新世代撤销旧许可的设计；世界是否执行必须依靠证据对账，不能直接再次start计划。

不要求本轮把Minecraft改成事件溯源数据库。应先列出副作用前/后、结果前/后、区块保存前/后等故障窗口，明确哪些状态能确定、哪些须UNKNOWN/隔离。七日引用感知归档和非投射物截止分别实现，活动重试/投射物/别名/许可引用延长保留。历史记录与实时授权分开后才能安全压缩。

### 8.3 合并按可恢复迁移处理

## 9. 网络、错误与客户端状态

错误分为稳定机器码、可本地化显示消息及有界参数；RetryDisposition明确不重试、刷新状态后重试、查询既有结果或人工核对。不得解析reason文本决定重发，也不把UNKNOWN视为网络超时后可自动再执行。

请求读取connection/实体实例、世代、会话/别名、operation负载与选择revision。解析限制包括字节、集合数、字符串长度、数值有限性、合法枚举与嵌套结构；字节上限不证明计算成本有界。响应选项/路径/日志也需有界，不能只保护C2S。

世界读写遵循实际线程契约；把处理排入主线程后仍要复验当前连接/实例和权限。网络正常TCP顺序与应用回调延迟/重试/重连是不同问题，测试描述不能笼统声称TCP随机乱序。

客户端保持一个交互状态所有者：Idle、Targeting、Querying、ContextMenu、AwaitingServer、Executing、CancelPending等职责。未提交取消使查询身份失效；已提交取消等待权威终态；UI检查目标和可执行目标不同，但不能保留旧菜单绑定却显示新目标。Screen/输入框/同意弹窗优先，失焦清合成输入。

关联：G19/G29/G33/G35/G38；证据E03/E12。

## 10. 表现、粒子、相机与时间交接

世界模拟暂停与表现运行分离。表现事实快照用于重追踪/恢复，挥手等一次性事件按身份去重，不用历史重放触发游戏关键帧。

独立年龄可以用于装饰，但不能把相差很大的两个绝对年龄线性混合返回原版。当前公式存在240→191→142→93→44的反例，动画采样时间会倒退；需要按通道采用相位/姿态混合、片段完结或明确定义的偏移交接。禁止改真实实体tickCount“修动画”。

渲染只消费这一客户端更新周期的不可变表现快照，不在每次阴影/轮廓/第一人称提取时再次推进。使用物品进度来自权威执行；粒子仅调用审计过的纯视觉发生器，不补跑完整tickEffects/updateUsingItem或再tick一次ParticleEngine。

`.109`统一render state扩展在extract/finalize之后；修改位置/尺寸可能与先前阴影派生结果不一致。通道适配要声明字段依赖，早期读取的手部/物品姿态另放固定版本桥接层，不把末端hook当万能接口。

箱盖等需要区分接收状态/演出信号与连续插值；不要放行全部block event。战术镜头环境采样只在已加载范围和明确预算内调整，不移动玩家、不强加载区块。

CameraRig独立拥有焦点、姿态、距离、地形约束和碰撞恢复；不影响角色体型/物理或表现适配状态。CAM-01本轮仅记录，不在此选择未经验证的高度策略。

关联：G36/G45/G46；证据E11/E16。

## 11. 计算预算、缓存与诊断

按连接/会话/实际server tick设置可观测的查询数量、候选数、路径扩展与总时间/工作量预算；注册器上限和单条ByteBuf大小并不替代累计预算。预览可合并并作废旧查询，但已接受的执行/费用不能被静默丢弃。

实时MinecraftCellProbe必须在许可线程；要异步计算只能使用明确冻结的纯值快照，并在执行前复验。缓存键依赖选择/物品/姿态/区域及相关世界观察revision，不能把上次preview当永久授权。不要为改善性能取消服务端执行复验。
