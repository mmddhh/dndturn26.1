# DNDTurn 战斗架构与规则决策

本文件记录战斗架构与规则取舍的理由，不维护实现进度。功能缺口与规则疑点统一见 [M3 acceptance](M3_ACCEPTANCE.md)。规则来源以 [dndrule.txt](dndrule.txt) 为准；后续有效修订以 [游戏规则](DECISIONS_RULES_CHECKLIST.md) 为准。`docs/dndturn-main` 是旧版行为参考，不是可直接移植的实现。首发目标为 NeoForge 26.1；Forge/Fabric 1.20.1 与 NeoForge 1.21.1 保持构建兼容，战斗功能暂不启用。

## 实施原则

- `common` 保存 Java 17、无 Minecraft 依赖的规则、状态、快照、因果链和结果；26.1 target 负责实体解析、原版执行、存档、网络与显示。
- 服务端捕获不可变快照后授权操作；Minecraft 执行后，将真实效果与规则状态作为一个不可变步骤发布。世界副作用不能回滚；同一操作 ID 不能重复扣费、执行或发布结果。
- 旧版通过 `teleport/setPos` 模拟移动、`setNoAi` 长期接管 AI、攻击演出移动实体、无授权清零无敌帧的实现不得移植。旧版 `HIDE` 和特定实体行为若缺少明确语义，仅记录缺口，不按实体类型补特判。

## 入场、敌对与多人

- 仅玩家主动发起回合制。候选 Encounter 的几何锚点来自发起时发现范围内所有实体的中心；参战队列与几何锚点分开。候选者每个回合结束时，服务端审查 mob 当前 target；有明确敌对关系则进入战斗。既有影响范围内的攻击行为即可触发开战，不要求命中或生命损失。正式开战时全员重新掷先攻，触发开战的合法攻击消费一次动作，重掷不返还该消费。
- 敌对关系是实体之间的有向关系，不以“玩家方/怪物方”二分；一个 mob 可以有多个敌对阵营。每场 Encounter 每名发起者仅有一次首攻资格，候选与正式阶段共享；规则状态在首次合法攻击登记时消费资格，未命中或重掷先攻不返还。服务端在登记前捕获目标当时的 target；生物未以发起者为 target 时，该次命中检定获得优势。这样非法请求不会消耗资格，下一场 Encounter 重新计算。若 target 不足以表示某类实体的索敌语义，必须先定义等价适配，不能猜测敌意。
- 当前不支持 PvP；预留外部组队模组提供关系信息的接口。区域重叠时取当前回合实体先攻最高者所在会话为主 domain；成员可即时管理，正式合并在回合结束后的下一环境回合入口提交。存活投射物保留因果 ownership，按环境回合调度，不阻塞合并；合并使用首次建场的发现和采样规则重新生成固定场地。先攻相同及环境阶段无当前实体时使用稳定 tieBreak 和会话 ID 裁决。
- 多人同意游戏规则默认关闭。开启后，玩家按键只发起请求并广播给范围内玩家；等待期间不暂停原版 tick 或既有事务。全员同意后才建立候选 Encounter。拒绝、超时或掉线使请求失效，原版活动继续，不重放交互。

## 时间、区域与移动

- 战术参与和模拟暂停使用同一个固定场地。发现范围内所有实体的中心是固定锚点；水平几何为这些锚点的凸包向外扩张圆盘，竖直范围为锚点最低 Y−16 至最高 Y+16 的平面包络。方块按自身中心、实体按自身实际中心查询同一连续区域；普通成员变化不重画，合并重新采样生成。半径与水平发现尺寸保持显式配置参数。不能用发起者单中心 AABB 或整区块替代场地。
- 区域外世界保持原版 tick；区域内只暂停模拟推进，外部变化可经入域分类与规则约束进入。环境回合只推进明确归类的对象；外来箭矢首次入域须分类，原 owner 死亡或离线后的投射物转环境调度，并保留历史来源。投射物不设置模组主动超时。环境 tick 预算只有在实际获准推进后结算。全局冻结只使用原版服务器级模式，不用它实现局部 Encounter。
- 箭矢穿过固定场地本身只证明空间归属；原版运动段的成员碰撞或可信目标锁定才证明攻击意图。这样战术未命中仍能触发射手介入，同时不会让掠过场地的箭凭空增加成员。可识别射手的发射快照保存历史身份；死亡和离线不复活行动资格。跨会话射手先进入因果合并，关键来源或组件证据缺失时在碰撞副作用前拒绝。
- 自然环境伤害的战术语义未定，不能把有发射者的箭矢伤害自动归为无来源环境伤害。区域计划 tick 必须保留相对到期顺序，重载后不能重复执行。
- 移动最终以 tick 计费；距离只作路径提案、显示和结果观察，不进入运行时费用换算。普通主动移动 tick 扣 1、水中扣 2、起跳附加 1；空中仅有主动水平输入时计费，被动位移/位置纠正不扣，零位移免费，同 tick 多包只结算一次。骑乘和复合位移见 M3 文档 Q06。路径执行前重新核验足迹、占用与能力。

## 攻击与伤害

- 战术攻击使用 d20＋5；自然 1 必失手，自然 20 必命中且伤害翻倍。优势/劣势各自不叠加，二者抵消。攻击动作一经合法提交即消耗，无论是否命中。
- AC＝向下取整的原版护甲值＋持盾 2。伤害基础值读取武器提供的攻击伤害属性；命中后扣除向下取整的护甲韧性值，最低为零。AC 和固定减伤只由一个换算函数产生，数值平衡应调整该函数的输入/系数，不散落在执行代码中。原版护甲、盾牌、附魔与抗性不对同一战术攻击再次减伤。
- 抗性/免疫应按伤害类型分别减半/归零，但适用范围与重启条件按规则 H02 执行。环境伤害也暂不按攻击处理。
- 战术范围内合法攻击/受伤入口核验后消除已有受伤无敌帧，覆盖延迟命中，并控制该次战术伤害不生成新的受伤无敌帧。非法请求不得先修改目标；旧版无授权的逐次攻击清零不可恢复。每个来源、受伤入口和事后实际生命变化使用同一因果链。
- 战术伤害只结算一次已授权的减伤，保留原版吸收生命与装备耐久等副作用。所有击退路径受 gamerule/config 控制；默认一次战术攻击无击退，启用后合法击退按原版碰撞立即响应。

## 恢复与验收

- 恢复规则明确的移动、攻击、疾走、撤离、回避、协助、进食饮药、借机攻击、先攻、HUD、格子显示和纯视觉战术镜头。保留自然实体位置与原版导航/碰撞。特殊实体只采用其可验证的原版通用能力；苦力怕引信、末影人瞬移、飞行/游泳/boss 的战术特殊规则在明确语义前不做单独特判。
- 存档保存 Encounter、操作 ID、快照版本、待决操作证据、AI Lease 和结果日志。重启后如无法确定世界副作用是否发生，发布“结果未确定”并释放控制权，不盲目重放。归档默认保留 7 个游戏日，期限集中配置。
- 验收必须分别覆盖服务端原版 tick 路径、同意与合并、重复消息、部分移动、伤害取消、重连/死亡/换维度、存档重载、客户端预测和四个 target 的构建。功能入口只有在这些场景通过后才能启用。

### 旧源码功能取舍

| 旧版功能 | 决策与依据 |
| --- | --- |
| `CombatManager` 的手动入场、回合与先攻 | 按玩家发起候选、target 审查和正式开战重建；不复制持有 `ServerLevel`/实体对象的旧状态。 |
| 怪物取得玩家 target 后自动开战 | 不恢复自动发起；target 是玩家候选回合审查敌对关系与偷袭的输入。 |
| `GridPathfinder` 可达格与移动计划 | 算法放 `common`，26.1 碰撞探针检查足迹；原版移动完成后按实际效果计费。 |
| 旧版近战、疾走、回避、撤离 | 根据 `dndrule.txt` 重建；伤害和动作必须带操作 ID 与观察结果。 |
| `HELP`、远程攻击、消耗品、借机攻击 | 规则已有语义，纳入新行动系统；按实际规则重建，不以旧源码中的枚举或标志作为行为定义。 |
| `HIDE` | 当前规则没有潜行检定与效果定义，暂缓。 |
| 苦力怕引信限制、末影人定点瞬移及其他实体特判 | 当前规则没有相应战术能力、行动成本与中断语义，暂缓；仅按获准能力与明确模拟分类执行原版通用行为。 |
| `teleport/setPos` 移动、攻击演出位移、`setNoAi` 接管、无授权清零无敌帧 | 与架构和已确定受伤入口政策冲突，不恢复。 |
| HUD、格子和战术镜头 | 仅恢复显示与选择；不得修改真实实体位置，所有选中动作需提交服务端验证。 |

## 原型入口的范围决定

2026-09-24 允许单独默认关闭的单玩家/Zombie 按键原型，用于正式入口开放前验收。该例外仅缩小原型交付范围；内存 held-tick 在正常退出/卸载/停止交还，不承诺崩溃恢复。它不撤销正式会话持久化、多人及客户端验收要求，详见游戏规则第 0.7 节。

## 2026-09-25 合并修复的明确修订

用户进一步明确：无敌人也可主动进入回合制，允许纯玩家与环境阶段循环。建场不以找到 Zombie 为前提；已支持 Zombie 的选取仍可加入成员，无目标时只登记获准玩家。没有敌对关系保持候选阶段，不为建场伪造敌意或自动结束；沿用现有权威轮转、预算和同意流程。客户端无会话 START 使用协议版本字段 0，不使用旧 -1 哨兵；服务端继续拒绝非法版本。

用户要求保留已接通的正常 tactical、网络意图与会话调度；旧原型开发开关不再限制这些入口。已有正常建场、Zombie 统一目标选择、共享鼠标控制是修复基线，不重复降级。

用户确认主动 EXIT 必须先让实体中心离开自己的活动场地。场内拒绝时保留成员、UI 和资源，避免先移除界面再被区域冻结；不以传送、场内豁免或提前结束他人会话解决冲突。死亡、掉线、换维度、卸载按独立生命周期处理。

用户确认 UNKNOWN 涉及的存活箭持久隔离：没有可核对证据前不推进、不产生新效果、不自动销毁、不加超时，也不因会话结束恢复原版。这是普通已知投射物结束调度政策的明确例外，优先于早期笼统的“UNKNOWN 释放控制”。

用户确认本人合法回合免费整理个人背包、装备与热栏；此权限不包含丢弃、外部容器、合成、物品使用或特殊移动。同效果的不同原版包入口须执行相同能力检查。

本轮用户选择暂不启动普通 dedicated server；不修改其独立测试目录的 EULA。GameTest 物理服务端和集成客户端验证不代替普通 dedicated、双客户端、重启与崩溃验收。

## 2026-09-25 后续客户端控制修订

本轮用户要求正常有效会话自动启用独立虚拟镜头，同时允许明确切换回获准角色控制；替代旧“手动可选纯视觉镜头”的默认进入行为。镜头不改变真实玩家位姿、模式、飞行、碰撞、网络位置和资源，不请求额外区块。Screen/同意模态/失焦属于临时输入接管，不改变用户模式；等待同意继续世界模拟。攻击必须明确选择当前会话目标，取消旧 hitResult 回退。

用户本轮明确要求运行客户端与独立服务端，优先于上段较早轮次的“暂不启动”选择；实际验证与边界见当前三份交接文档及固定版本 client-control 契约。测试账号管理员权限不从运行测试的授权中推导。

## 2026-09-25：目标计划与原版接受点

根据用户对 gameplay-chain 任务书的明确确认，采用候选阶段预算移动/非敌对交互、实际攻击开始激活、原版接受放置/破坏/使用时收费、免费开箱及受限存取、基础弓弩雪球。具体规则归入 `../03_PLAYER_RULES.md` 第 14 节。

PLAN 是规则层唯一根记录，MOVE 与最终能力为顺序子步骤。根计划预留动作但不扣费；受限 beginPlanStep 不赋予普通子操作授权。伤害仍走 EffectPermit。服务端计划执行器仅持有 UUID/值与路径提案，不成为第二套成员状态。首次攻击重排先攻时，计划终态之前暂停后续 Mob 回合调度。

持续挖掘和食饮/蓄力只推进获准的 gameMode/item 子系统；不开放整个玩家身体 tick。免费方块交互使用 .84 useItemOn 的局部桥接隔离物品回退。根意图与结果持久化；恢复不重放未确认的世界副作用。技术接入与验收证据见 `../version-differences/neoforge-26.1.2.84-gameplay-chain.md`。

## 2026-09-25 通用行为系统修订

用户确认采用原版通用交互链与完整特殊适配器。稳定行为 ID、版本、目标类型、手别、位置条件、准备/开始/推进/观察/取消/恢复构成扩展契约；行动枚举仅作规则成本分类。服务端发现多个选项，客户端不根据物品类型猜测行为。方块自身交互取消类名白名单，保持保护事件且禁止物品回退；菜单权限独立。无法约束的额外副作用要求专用适配，不用默认近战填补。旧未绑定行为的持久计划迁移为显式未解析行为并 UNKNOWN 释放，不重放。


## 2026-09-26：161358 修复决策

用户要求目标式交互替代独立能力假选择。ClientTacticalPlan 独占 typed target、确认物品、行为、查询 revision 和运行 operation；ClientControl 只拥有镜头与输入接收者，Overlay 渲染投影。选槽和发现由同一服务器线程请求完成，原版选槽包不能覆盖查询确认；运行中换槽明确拒绝。普通动作费用与首次合法攻击激活时点不变。

同步近战先发布 ATTACK 与 PLAN，再处理死亡/离场。嵌套世界效果深度延后清理，已发布结果不可改写；真正不确定结果仍 UNKNOWN，尚未开始行为的计划离场为 INTERRUPTED。S2C 终态从规则结果构造并携带 publishedVersion；取消后结束回合等待对应权威版本。

固定版本的 BlockPlaceContext 决定可替换格/邻面落点；门上半、床头与双层写入一起事前授权。未知 BlockItem/Block override、自定义放置组件、打火石额外效果、桶替换复杂方块等明确不支持，不通过回滚扩充保证。原版及 loader 保护事件仍保留；只在写后触发的第三方保护事件不能构成模组事前授权保证。

隔离恢复测试实例不是运行服务，不得把运行服务的 scheduled tick 队列索引注册为自己的。恢复值审计与平台调度 ownership 分开。
