## 1. 目标、依据与范围

### 1.1 最终目标

将当前“玩家物品行为系统＋Mob 专用回合脚本”改造成以下公共执行链：

```text
玩家输入适配                    Mob 决策适配
    │                               │
    └────── 能力调用提案 ─────────────┘
                    ↓
      执行者／能力来源解析与规范化
                    ↓
       统一规则校验与有限执行授权
                    ↓
    一次行动计划：必要时接近 → 复验 → 执行
                    ↓
      效果观察、费用提交与单一根终态
                    ↓
   只读投影／演出事件／检查点／策略结果反馈
```

成功标准不是类名相似，而是：**新增一种经过审计的能力来源或 Mob 适配，只新增并注册差异代码，即可使用既有授权、计划、费用、结果和恢复边界；不需要再次修改核心中的物种分支。**

本文的“能力”指玩法能力，不要求其与 loader 中同名的机制一一对应，也不要求引入一个新的全局属性／技能树系统。

### 2.2 保留而非重做

必须保留唯一 `CombatEngine` 规则权威、稳定 operation 身份、父子效果许可、一次普通动作及独立移动费用、不可变结果、候选阶段接近机制、原版移动／碰撞／受伤链、持久未知箭隔离、客户端投影顺序与现有支持白名单。

## 3. 能力模型与标准化合同

### 3.1 六个概念必须分开

| 概念 | 回答的问题 | 不应包含或暗示的内容 |
|---|---|---|
| 能力定义 `AbilityDefinition` | 能做什么，支持什么目标和执行合同？ | 不表示任意实体都拥有它；不持有某次运行对象 |
| 来源绑定 `AbilityBinding` | 为什么这个执行者拥有这项能力？ | 不自动扣费，不授予执行许可 |
| 当前可用性 `Availability` | 当前资源、来源、目标和环境允许怎样使用？ | 不是无限期许可；不可用不等于永远不拥有 |
| 调用意图 `AbilityInvocation` | 本次明确想用哪个绑定作用于什么目标？ | 不是客户端可信的伤害／成本／最终位置 |
| 执行许可 `ExecutionPermit` | 这次被允许推进哪些步骤、子系统和效果？ | 不凭有 operationId 或同 domain 自动成立 |
| 运行记录 `AbilityExecution` | 已到哪一步、产生了什么、如何结束？ | 不与定义、UI 预览或持久对象共用可变状态 |

注册表中有一项定义、执行者拥有来源、此刻可用、本次获准，必须有独立判断。禁止用一个 `supported` 或 `enabled` 布尔值同时替代六个问题。

### 3.2 能力定义的最小合同

定义必须提供或引用：稳定 namespaced ID、语义版本、可绑定的来源类别、目标合同、执行者端口要求、规则费用分类、有效接受／提交事件、接近与执行条件、有限副作用类别、取消／恢复合同，以及可选的显示描述。

“提供或引用”不意味着一个巨大接口实现所有细节。可以将定义的纯值元数据与 target 内执行驱动分开，但需要能够验证二者对应同一版本。

**分类不能继续由单一枚举包办。**允许保留小型内置分类供 UI、账本或旧协议使用，但不得再由它同时推出“必须有物品”“只能点实体”“收一次动作”“最终调用近战”。新能力身份由注册 ID 表达；费用由现有规则分类裁决；目标与效果按自己的合同验证。

定义不是收费权威：适配器不能把一项攻击标成免费方块交互来绕过规则。无法在已定规则中合法归类的新能力，应拒绝正式启用并记录缺失规则；不能默认免费，也不能擅自增加资源种类。

### 3.3 执行者引用和能力端口

`ActorRef` 至少能定位稳定根实体、维度与适用会话；运行时另核验实例、世代、成员资格和控制者。使用现有生命周期代次能解决的问题，不另造互相竞争的全局版本。

target 的执行者解析器按需提供受限端口，例如玩家库存／手别、玩家输入移动、Mob 导航、身体姿态、天生攻击或受击状态。没有某个端口返回明确不支持，不提供返回空值的万能实体包装器。

端口不能成为任意世界修改的旁路。世界写入仅在被授权的执行上下文内开放；发现和决策应拿到只读视图，而不是同一个携带 `ServerLevel`、`attack()` 与 `setPos()` 的万能对象。

**玩家可以有天然能力，Mob 也可以使用装备能力。**来源种类与执行者类型是正交维度，不新建“玩家永远物品、怪物永远天生”的第二套硬编码。

### 3.4 来源绑定、拥有关系与失效

至少支持以下语义。生产使用范围受规则和现有适配约束；状态来源可先由独立测试证明，不新增正式状态技能。

| 来源 | 绑定证据 | 主要失效条件 |
|---|---|---|
| `ItemSource` | 所属执行者、容器／槽位／手别、选择修订、必要堆栈内容与组件 | 合法换装、转移、损坏、关键组件改变、容器或实例失效 |
| `IntrinsicSource` | 执行者类型／已注册提供者、能力 ID/版本、相关身体或能力状态 | 实例替换、能力移除、形态或依赖状态改变 |
| `StatusSource` | 赋予者／状态身份、适用执行者、状态版本或有效证据 | 状态消失、授予关系撤销、期限或依赖失效 |

普通移动和方块自身交互不需要伪造 ItemReference；可由执行者的基础移动／交互能力提供。方块是目标及可交互性质的提供者，不把“看到了这个方块”误当成玩家已获免费执行许可。

绑定可以从当前权威装备、状态与适配派生，不要求另存一套“技能拥有表”。只有新增真实授予状态时才定义其持有者和保存合同；缓存不是新的拥有权威。

堆栈哈希证明内容，不天然证明同一物品实例。实现必须声明自己保证的是内容等价还是更强的来源连续性；后者需要相应容器／选择／变化证据，不能凭相同 SHA-256 声称实例不变。

执行中的合法自身变化必须被识别。例如扣箭、减少食物数量、武器耐久变化应产生有来源的已确认变化，推进后续预期证据。不得使计划因自己的合法消耗自动失效，也不得通过每 tick 接受任意最新堆栈来掩盖外部换物。

### 3.5 当前可用性不是一个 reason 字符串

至少区分：可以原地执行、需要接近、目标尚未选择、当前被规则或来源阻止、缺少适配、以及预算内尚未完成评估。返回稳定原因和必要依赖版本；不得将“没有计算出路径”假装为“已经证明不可达”。

能力发现可以报告超出当前射程但能尝试接近的能力，不因“此刻不能原地攻击”直接删除该能力。行动提交仍独立验证剩余资源、可达执行位置与接近失败的处理。

### 3.6 规范调用的值结构

以下为**语义示例，不是可直接编译 API**：

```text
AbilityInvocation
  requestIdentity      operation、原始请求身份／版本证据
  actor                 根执行者和适用会话
  definition            ability ID + behavior version
  sourceBinding         来源类别、提供者、绑定修订及来源证据
  target                有类型的实体／部位／方块／地面／自身等目标
  parameters            该能力已注册、有限且有类型的参数
  observedDependencies  所依据的选择、规则及必要世界依赖
```

手别和槽位只属于需要它们的来源分支。目标参数必须有明确解码与验证器，不用任意 Java 类型、可执行回调或无约束 `Map<String,Object>` 穿越协议。可扩展参数的 codec 留在 target；common 只保存经过限制的纯值表达。

调用者身份不直接等于执行者身份：玩家来源必须通过当前连接核验对 actor 的权限，AI 来源通过当前服务器调度与适配权限核验。相同 actor 不能在同一时刻被玩家入口和 AI 入口分别启动互不知情的根行动。

## 4. 状态所有者与模块边界

| 职责 | 权威或生命周期所有者 | 允许依赖 |
|---|---|---|
| 成员、阶段、敌对、先攻、资源、最终结果 | 既有 `CombatEngine` | 纯值与受验证的规则命令 |
| 静态能力定义与匹配合同 | target 启动期注册器，按版本冻结 | 定义／工厂；不持有某世界或玩家 |
| 能力来源解析 | 当前服务器执行者／能力提供者 | 服务器线程的只读世界事实，返回值快照 |
| AI 私有决策记忆 | 明确的策略运行实例 | 已审计感知与历史反馈；不是第二套仇恨／资源权威 |
| 行动计划与跨 tick 租约 | 每服务器执行协调器 | 规则视图、适配版本、当前实例和驱动 |
| 世界修改 | 原版或审计过的驱动 | 当前许可、受限端口及合法线程 |
| 当前退出暂停豁免 | 明确的实时授权所有者 | 既定退出规则、成员代次及来源回执引用 |
| 历史记录与恢复证据 | 历史／持久化职责 | 不可变规范值与必要引用 |
| UI 选择／查询 | 单一客户端交互状态所有者 | 当前有序投影和选择代次 |
| 动画状态／时间 | 客户端表现运行时＋已注册通道适配 | 显示事实与事件，不访问可写规则余额 |

common 保持 Java 17，无 Minecraft、loader、Mixin、平台网络／Codec／渲染依赖。actor、source、target、费用和结果等确实同义的纯值可共享；`ServerPlayer`、`Navigation`、`Brain`、`ItemStack`、连接及渲染对象留在 target。

运行上下文可以短期持有平台引用，但必须有明确开始、推进、撤销、销毁和实例复验；不能将其复制进网络、结果历史或持久 DTO。拆出 façade 后若仍由多处修改同一 Map，或仍由核心类持有所有生物差异，不算重构完成。

建议按职责组织 `ability`、`actor`、`execution`、`ai`、`presentation` 等包，但不要求一次机械搬迁所有文件。优先交付一条完整纵向链路，再提取由第二种真实适配证明有复用价值的部分。

<a id="registry-discovery"></a>
## 5. 注册、能力来源与纯发现

### 5.1 注册器职责

分别支持能力定义／执行驱动、执行者能力提供者、目标／受击适配、AI 策略及客户端表现适配的注册。可共享注册基础设施，但不要构造一个同时要求实现以上所有方法的万能 `MobAdapter`。

注册必须明确：ID/版本、匹配条件、需要的端口、执行侧与线程、支持效果、恢复策略、冲突处理及冻结时点。重复 ID 拒绝；多个匹配不得依赖 HashMap 或模组装载顺序碰巧取第一个。采用确定的优先级／覆盖声明，或拒绝歧义并给出诊断。

当前精确类型白名单应迁移为内置注册项。未注册时保守拒绝相应世界行为；不要把精确检查直接扩大为任意 `LivingEntity`／`BlockItem` 来假装完成兼容。

### 5.2 纯发现与显式选装备

玩家选择流程必须拆成可独立测试的操作：

```text
SelectEquipment 命令
→ 核验本人回合、库存整理与运行计划状态
→ 确认 SelectionSnapshot
→ DiscoverAbilities 查询
→ Options（绑定来源、目标及查询修订）
```

允许保留一次“选择并查询”的网络往返，但 AI、悬停和预览必须可以调用不换装的纯发现入口。取消预览不撤销已经合法提交的装备选择；正在执行计划时按既定规则拒绝换槽。

查询不得改变位置、库存、资源、伤害、持续使用、Goal/Brain 状态或执行租约，也不应消费会影响随后命中检定的规则随机序列。必要缓存只属于派生状态，必须有界且不改变游戏观察结果。

发现可先给出基础可用性，再在预算内评估接近路径；所有阶段关联同一查询身份。数字热栏与 UI 点击使用相同选择命令，不靠延迟一 tick 解决顺序。

### 5.3 重载、缺失与兼容

运行计划固定定义、驱动及来源合同的语义版本。初版可以禁止运行中替换相关注册内容；若支持重载，必须保留旧运行版本或走明确中断／释放，不能把旧计划交给同名新行为继续执行。

服务器缺失能力必须拒绝执行；客户端缺失专用表现可使用通用描述或保守显示降级，但不能影响服务器规则。客户端不知道参数结构时不能自行猜参数或伪造调用。

同 JVM 的其他模组不是隔离的恶意脚本沙箱。注册与许可保证仅针对审计覆盖的调用链；外部模组任意直接改世界的情况应作为兼容边界和冲突诊断，而不是承诺绝对阻止。

<a id="action-entry"></a>
## 6. 玩家／AI 共用的行动入口

### 6.1 一个规范提交入口，不必一个网络入口

玩家包处理器和 Mob 决策器可以各有输入 DTO，但必须到达同一个服务端规范提交入口。其职责为：

1. 核验调用来源，解析 actor 的当前实例、服务器世代、会话、成员资格及控制权。
2. 根据原始 operation 身份检查账本；相同规范负载返回已有状态，负载冲突拒绝。已完成请求不能被新的版本检查绕过后重新执行。
3. 解析能力定义、来源绑定和有类型目标；验证参数、支持范围、来源证据及必要依赖。
4. 让规则权威检查阶段、资源、关系和必要的预留；调用者不能提交可信成本或伤害。
5. 形成有界执行提案，检查实际作用范围与执行驱动；获得本次所需的有限许可。
6. 创建唯一根行动运行状态，推进接近／执行，并观察费用与效果。
7. 发布一个规范根终态及只读反馈；释放控制，通知策略继续决策或 UI 收敛。

具体内部步骤可合并，但以上判断不得因为请求来自 AI 就被省略。规范化可以解析当前事实，却不能把一次旧请求自动换成另一件武器或另一个目标。

正常路径必须只有一个根计划所有者。同一实体同一阶段只有一个主动身体驱动；合法反应、伤害子操作和环境延迟效果通过明确的嵌套／独立调度合同运行，不受“已经有父计划”笼统阻止。

### 6.2 原始请求与执行中的依赖分开

原始规范负载及其语义版本保持不可变，用于去重和历史。计划自己的移动、费用或物品消耗引起的版本变化，记录为已授权步骤的结果；后续复验使用推进后的预期事实。

不能每 tick 都拿最初的 Encounter version 与当前值比较，使计划因自己执行而过期；也不能因此取消物品、目标、作用域与实例复验。

收到超时或断线不创建新的 operation ID 盲目再试。先查询原请求结果；只有已经确认旧请求被拒／取消且不会继续产生效果时，新的用户意图才可以建立新请求。刷新状态后提交改变了来源或目标的行为，不能继续使用旧 ID 换义执行。

### 6.3 旧入口迁移

旧 `ATTACK`、`MOVE_BEGIN` 等玩家公开请求不得恢复直接执行旁路。选择显式拒绝或经兼容层转换到统一入口，并保持旧 operation 的规范负载／历史查询语义。

Mob 内部原有攻击、伤害观察和导航方法可保留为受许可驱动，不再同时作为不受统一能力来源校验的另一套对外行动入口。必要的兼容包装只允许单向委托，不允许新旧执行器分别扣费和产生世界效果。

对 `DASH / DODGE / DISENGAGE` 等既有行动，迁移其明确的规则能力或统一命令处理，不额外伪造物品来源。`START / EXIT / END_TURN` 是会话／回合命令，不必强行改成物品或世界技能；但必须协调运行计划终结，不能在计划仍持有身体控制时提前轮转。

<a id="target-execution"></a>
## 7. 目标、接近与原版执行

### 7.1 目标合同

保留当前实体、方块、地面和自身目标。框架不得再从“ATTACK”一词强制推出单实体形状；方向、区域或复合目标仅在具有已审计合同的能力需要时增加，不预先实现通用法术编辑器。

| 目标 | 验证内容 |
|---|---|
| 实体／部位 | 稳定身份、当前实例、根实体映射、存活／可交互、关系、成员和 domain、具体受击能力 |
| 方块 | 维度、位置、命中面／点、必要状态、交互分支、真实写入范围和保护 |
| 地面／执行位置 | 合法站立或对应移动模式的位置、体型、通路、加载边界与剩余预算 |
| 自身 | 能力明确支持 Self、来源有效，不能借无目标绕过 actor 校验 |
| 后续扩展 | 该能力注册的参数形状、几何与效果范围；无解析器即拒绝 |

攻击者能力、目标受击适配、关系规则分别验证。一个目标可受已支持的攻击，不必已经具备完整自主 AI；进入先攻也不能自动表示可被一切效果作用。

大型根实体与命中部位分开：根实体承担资源和回合，部位只承担合法命中定位与具体效果映射。此次可以先建立映射合同及测试，不实现完整 Boss 规则。

### 7.2 接近是行动的一部分，不是先发一条无关移动

计划选取满足该能力条件的合法执行位置集合，而不是目标所在格。条件包括对应射程／交互距离、视线、体型碰撞、命中面与已加载空间。

已经可以执行时不强行移动。不能把所有范围抽象为同一个固定整数半径；射程、预览搜索半径与路径搜索预算是不同参数。

接近过程中按既定规则独立结算实际主动位移；动作不足不能被预览绕过。无法在剩余预算内接近、目标变化或路径受阻时，给出稳定原因并按合同中断或受预算约束重规划。重规划不得自动换能力、物品来源或目标，也不得每 tick 无限重算。

### 7.3 身体驱动与所有权

玩家执行继续走现有输入、网络权威校验、travel 与碰撞；Mob 执行继续使用适配的 Navigation、control、travel 与碰撞。相同计划协调器调用不同驱动，不复制 Mob Navigation 给玩家，不调用 teleport/setPos 模拟行走。

每个驱动必须提供获得、推进、观察、中止和幂等释放的合同。外部模组替换了路径或控制字段时，不无条件恢复旧值覆盖它；无法证明仍拥有控制时，停止本方推进并记录原因。

移动体型、姿态和模式作为有限依赖捕获；验证整条边的扫掠、支撑、台阶／跳跃，不仅验证终点。没有加载的数据不是可通行，也不能为完成路径强制加载整个区域。

<a id="outcomes"></a>
## 8. 费用、效果、终态与释放

### 8.1 执行阶段

推荐表达以下有界阶段，名称可调整：

```text
已接受／已授权
    ↓
接近（可选）
    ↓
到位复验与准备
    ↓
执行开始／原版接受点
    ↓
执行推进与效果观察
    ↓
结束聚合与控制释放
    ↓
单一规范终态
```

“执行开始／原版接受点”由具体能力确定，不统一等同于 `start()` 方法被调用。若 prepare 会改变身体朝向或其他世界状态，它必须在相应许可内执行并计入可观察过程，不能被冒充为纯验证。

需要等待反应、连续使用或延迟反馈时，使用明确的有界等待状态及适用时钟；不增加自由重入的脚本工作流。合法伤害子操作仍可嵌套，深度和数量按已有保护边界处理。

### 8.2 费用规则保持不变

| 情况 | 必须保持的行为 |
|---|---|
| 选择、发现、预览 | 不消耗普通动作，不产生攻击效果 |
| 合法装备整理 | 按 03 的本人回合免费整理规则；不等于免费使用物品 |
| 接近 | 只按已发生的合法主动位移结算移动，不提前收费为攻击 |
| 合法攻击实际开始 | 消耗一次动作；未命中、零伤害不返还 |
| 放置、破坏、物品使用 | 在已确认的原版接受边界消耗一次动作；开始前拒绝／未处理不收费 |
| 持续使用或破坏 | 一次根行为收费，不按包、tick、命中段或子效果重复收费 |
| 方块自身交互 | 零普通动作；必要接近照常收费，不回退手持物品逻辑 |
| 取消或中断 | 保留已发生移动、已提交动作和已消耗物品；不虚构世界回滚 |
| 无法确认副作用 | 记录已知分量与 UNKNOWN；不盲目退款、重放或判为没有发生 |

移动费继续按 03 的服务端实际主动位移归因规则，不按路径长度、节点或动画进度。旧的一次动作、反应、DASH 等数值不由本任务重定。

资源预留如实施，必须由 `CombatEngine` 可见且唯一管理，与消费和撤销分开；执行协调器不能再维护一份“可用动作余额”。物品实际变化属于平台事实，规则层记录其提交证据，不复制一个可以独立花费的物品库存。

### 8.3 三类结论独立记录

每次行动的聚合至少保留：

```text
EffectResult      已确认发生／未发生／部分已知或不确定的世界效果
ResourceCommit    已提交的动作、移动与物品相关证据
ReleaseResult     控制安全释放，或释放失败、需要隔离／停止调度
```

随后由唯一聚合入口决定规范根终态。`EffectResult` 中的确定性不以日志是否写出、release 是否成功或 `hurtServer` 返回值替代。

| 情境 | 结局约束 |
|---|---|
| 执行前拒绝 | 不产生新世界效果／动作费；释放预留及已取得的临时控制 |
| 攻击已合法开始但未命中 | 一次动作已经提交；不是执行前拒绝 |
| 部分接近后取消 | 移动保持已结算；尚未开始的能力不收费 |
| 世界效果已确认，release 抛错 | 保留效果和费用；记录控制故障，阻止不安全的后续调度 |
| 世界副作用是否发生无法确认 | 不可重放；保留已知部分，并按既定 UNKNOWN 与隔离规则处理 |
| 父计划执行结束时目标死亡／离场 | 先聚合已确认子结果，或等价地保护该结果，再进行清理；不得仅因离场覆盖成功事实 |

本文件不擅自增加新的 `Outcome` 枚举。实现必须给现有枚举与附加证据制定唯一、可测试的映射；若协议确需扩展，显式迁移。不能要求两个模块分别发布“成功”和“清理失败”两个互相竞争的终态。

### 8.4 取消请求与最终释放分开

定义清晰的取消／中断入口，以及无论正常完成还是异常都能使用的幂等 release。release 只能停止本执行拥有的输入、导航、持续使用或临时上下文，不触发一次新技能。

取消不是抢先改变已确认事实。若请求到达时效果已经提交，应返回实际已完成／已中断结局，不假装取消胜出并退款。客户端的 CancelPending 必须等待权威结局；重复取消只查询或推进同一次取消，不重复释放别人的控制。

如果某次释放失败，后续幂等释放或恢复对账可以继续尝试收束控制；该过程不能重启原世界动作，也不能倒改已经发布的效果记录。

<a id="ai"></a>
## 9. AI 策略与回合控制

### 9.1 决策视图和策略输出

策略输入至少包含：执行者与当前回合身份、已审计感知、规则关系、必要的目标记忆、来源有效的能力集合、剩余资源、已发生行动的结果及有界局势信息。

策略输出应为以下之一：明确能力调用提案、明确结束回合、或带原因的暂无决策／等待条件。执行协调器不提供“想做什么”的默认 Zombie 答案。

策略只读取决策视图，不直接伤害、移动、切槽或改规则资源。需要维护策略记忆或随机游走提案时，使用单独的决策状态与可控随机源，提交被选结果时明确更新；不能让一次 UI 能力查询消耗 AI 或命中随机状态。

### 9.2 感知、关系、偏好和合法性

这四层分别回答“知道谁”“与谁是什么关系”“优先谁”“现在能对谁使用何能力”。服务器能解析实体不等于 AI 感知它；持有当前 target 不等于拥有攻击许可；没有攻击目标也不等于任意副作用都允许。

保留多方有向关系和禁止 PvP 的既定规则。选择目标的策略不得默认把所有玩家作为敌人，也不得仅凭 Java 物种名替代已定关系。AI 重新选目标必须记录旧承诺中断／过期及新决策，不能在导航观察时悄悄替换。

### 9.3 原版语义适配

保留已经审计的导航、控制、感知信息和技能入口；不要长期 `setNoAi`、删除 Goal 或默认用一套新 AI 替代所有生物。

Goal／Brain 可能执行移动、攻击或更新记忆与冷却，不能跑一遍再“提取意图”。每个适配需声明可读取的状态、可运行的子系统及其副作用边界；`customServerAiStep`、外层 tick、运行中 Goal、Brain 和其他任务分别审计。

把当前 Zombie 选择逻辑迁为一个显式内置策略，并让它通过同一能力入口提交。保留已批准的非敌对地面路径／随机漫步策略；这种策略不授权工作、繁殖、攻击或未知 custom AI。

### 9.4 行动完成不自动结束回合

一次能力执行器只返回结果。回合控制器在结果安全收束后，根据剩余预算与策略重新决定，必要时继续移动或使用另一项当前合法能力。它不产生额外普通动作。

禁止无限重试同一个不可达提案、在每个服务器 tick 新建失败 operation 或永不结束的空决策循环。按有界决策预算、已确认局势变化和稳定失败原因控制重决策；预算耗尽须可诊断，不能静默丢掉已接受行动或擅自修改游戏资源。

未知 Mob 的支持分轴显示：可采样、可暂停、可入场、可成为目标、可移动、可执行某能力、可自主决策。保留已批准的入场政策；缺少策略或驱动时返回明确受限处理，不将其伪装成完整兼容，不直接放开全部 AI。

<a id="world-effects"></a>
## 10. 世界适配、伤害与延迟效果

### 10.1 有限读取依赖、实际作用范围与观察

每个能力驱动必须说明它依赖什么、可修改什么、从哪里执行、如何观察及如何释放。证据只覆盖本次行为必要的有限对象，不建立整世界哈希或万能回滚系统。

至少迁移已有伤害、移动、物品消耗／耐久、放置／破坏、持续使用和交互结果的观察。状态授予、生成、特殊容器等未实现类别，可以有类型边界和明确 unsupported，但不能返回空列表后声称“没有效果”。

方块状态字符串或物品类型相同不必然覆盖方块实体、容器内容和关键组件依赖；使用哪些依赖由具体能力明确提供。执行前与关键步骤重新核验，而不是只比较最终目标格。

### 10.2 攻击者与受击者两侧

将攻击者的技能驱动与目标受击适配分离。复用 `hurt` 只代表进入受害者链，不自动保留攻击者的特殊副作用；调用攻击者原版技能也不能造成第二次命中检定或重复伤害。

战术命中／伤害计算保持唯一入口。取消、免疫、耐久、吸收、击退、无敌帧和死亡各有明确证据及接受边界；其他模组的效果必须在审计范围内逐项接入。受击类型扩展不能通过删除所有类型检查而“通用支持”。

### 10.3 物品和方块行为

保持 `USE_BLOCK` 的方块自身分支与物品 `use/useOn` 分开。开箱的接受结果不授权任意合成、交易、丢弃或跨距离操作；菜单存取按 03 的独立许可处理。

放置必须在首个副作用前检查实际多格位置、加载、区域、保护和碰撞；邻居传播、流体、延迟 tick 与生成各有边界。只有事后保护事件时，不能承诺已经事前完成所有保护校验。未知 override 保守拒绝，禁止先写世界再用 `setBlock` 回滚冒充原子性。

### 10.4 延迟效果与能力本体解耦

射出投射物后，根行动可以按其合同完成；投射物继续由已批准环境调度和自身来源合同推进。根行动结束、射手死亡／掉线或换武器不自动删除历史来源，也不让存活效果变成无许可自由模拟。

发射时的能力／来源版本和必要参数需要捕获，后续命中不能改用射手现在手持的武器计算。延迟效果通过明确来源、当前调度域和效果许可执行，不持有可任意调用的旧运行对象。

一次技能允许多个有界效果不等于每个子效果再扣一次普通动作。根结果汇总不能与子结果重复相加；效果去重不能只用目标 UUID，因为同一合法技能可能有多个不同效果序号。

不新增模组主动投射物超时。存活未知箭保持持久隔离；具体七日操作截止与归档规则不应用作其寿命。

<a id="lifecycle"></a>
## 11. 时间、网络、恢复与实时授权

### 11.1 时间源必须有语义

分别定义世界日程、获准模拟步、能力执行进度、AI 记忆／冷却、确认窗口、归档／监视和客户端装饰时间。不得以一个全局 counter 或修改世界 `gameTime` 统一替代。

每个跨 tick 驱动声明暂停、恢复、中断、结束回合和服务器重启时如何处理时间。绝对截止不能被“没调用 tick”自动证明已经暂停；既有 400／100 实际服务器 tick 窗口及七游戏日政策以 03 为准，不在此重新调整。

框架验证需包含一个倒数计时适配与一个绝对截止适配，证明它们能按各自合同暂停／恢复；这不要求新增玩家冷却系统。

### 11.2 网络与失败分类

错误信息至少拆为稳定机器码、可本地化消息／有界参数和明确重试建议。建议类可表达“不重试”“刷新后重新提案”“查询原 operation 结果”“需要恢复核对”；名称可调整。

禁止解析 `reason.contains(...)` 驱动重试。文案变化不改变协议，UNKNOWN 不等于网络超时。C2S 来源绑定是待验证的声明，不是服务器许可；重连后需重新确认当前实例和来源。

请求与响应限制字节、数量、字符串、有限数值、路径及扩展参数；放入服务器队列后再次核验连接和实例。应用层迟到回调、重复、取消和重连要测试，不描述为 TCP 任意乱序。

原始 wire 版本、common 快照 schema 和 target envelope 分别演进。只变动确实需要迁移的轴，并提供迁移／拒绝矩阵；不按“都是框架升级”统一加号。

### 11.3 恢复和来源重建

检查点保存可审计值：规范调用、能力／驱动版本、必要来源和执行证据、已提交资源、效果与 release 状态，以及延迟效果身份。运行中的 Entity、Navigation、Brain、线程上下文或任意回调不可序列化复活。

恢复先验证候选，再解析当前实体和来源，最后安装允许继续的状态。来源已经改变、适配版本缺失或副作用是否发生不确定时，记录明确结果，不把原请求重新 start 来“验证”。当前不支持恢复继续的能力须明确声明并安全收束。

`SavedData` 更新不是会话与实体／区块同时持久化。至少注入并检验副作用前后、结果发布前后、物品／实体保存与模组检查点不同先后的故障窗口。不承诺任意崩溃下恰好执行一次，不丢弃原始损坏数据掩盖问题。

### 11.4 当前授权与历史回执

实时退出豁免应有独立记录，关联玩家、控制域／成员代次、合法退出原因、来源 operation 和撤销条件。归档历史回执不能改变当前控制；旧回执不能在重新入场后复活已撤销授权。

保留现有“无存活 Mob target 可场内退出”等已确认规则；这是授权存储职责更正，不是修改退出玩法。正常生命周期退出和用户主动 EXIT 分开处理。

会话合并按现有安全时点执行：准备并停放驱动、规则提交、幂等重绑定域／别名／held ownership／投影与来源、发布结果。不能把 canonical ID 替换当成全部迁移，也不能用重置资源消除冲突。每个失败点明确哪些事实已提交、哪些衍生绑定可重做；重做绑定不重放能力。

本任务对受影响能力的协议、检查点、授权和合并路径必须交付实际迁移。与能力框架无关的全部七日归档或所有跨域问题，不因本文存在就标成已经关闭；剩余范围仍留在 02。

<a id="presentation"></a>
## 12. 表现适配与客户端交互

### 12.1 表现是独立扩展轴

表现运行时负责实体／会话身份、已确认事实、事件去重、时间及生命周期。适配器持有自己的模型状态，声明待机、步态、攻击、使用、受击或纯视觉发射通道和字段所有权。

内置人形、Bat、掉落物也通过同一注册机制使用。不得持续向核心 Pose 添加每种 Mob 的字段；未知 renderer 不强制接管。客户端表现适配是否存在，不决定服务器能力的合法性。

持续事实可在重新跟踪时恢复；一次性攻击／受击事件按 operation、效果序号和接收边界去重。历史补收不重新播放全部旧演出。游戏关键帧没有伤害、召唤或消耗权限；服务器已确认的执行阶段可以驱动对应显示，但显示结束不能决定服务端效果已经发生。

### 12.2 时间与渲染接入

按客户端更新周期推进并生成可复用快照，渲染只采样。阴影、轮廓、第一人称或头像多次提取不能重复推进。

修复相差较大的绝对年龄线性交接；按通道使用适当的相位／姿态过渡、片段完成或有明确坐标变换的时钟偏移。验证采样时间不会倒退，不通过修改真实实体 `tickCount` 补救。

Render State 是主要入口；提前消费的手部／物品姿态由固定版本桥接处理。需要修改几何字段时核对 finalize 与派生数据顺序，不把末端 hook 当作万能入口。

只恢复审计过的粒子发生器／展示信号，不额外 tick 粒子引擎，不恢复带有状态期限或物品副作用的完整实体方法。箱盖等事件只在对应展示合同内桥接，不放开全部 block event。

### 12.3 目标式交互继续使用统一能力结果

玩家默认“选武器准备攻击、选方块准备放置”；一个物品多能力时显式选择。默认能力只能来自当前来源和服务器支持结果，不把 UI 类名匹配当作权威。

数字槽和背包共用已确认选择。菜单绑定其打开时的目标及来源；左键确认不重新拾取菜单下的世界。未提交查询／预览取消立即失效其身份，迟到回复不能复活菜单；已提交取消等待权威终态。

保留 `Idle / Targeting / Querying / ContextMenu / AwaitingServer / Executing / CancelPending` 等状态职责及 UI 优先级。结束回合先协调运行计划；键位迁移不得恢复旧“先开启手动移动、再只攻击附近”的主链路。

CameraRig 与 actor／presentation 分离。本规范要求该边界不被破坏，但 CAM-01 的具体地形跟随方案留待独立调查与修复，不在此假定根因或关闭状态。

<a id="budgets"></a>
## 13. 计算预算与诊断

查询、候选能力、路径扩展、重规划、AI 决策及环境调度具有连接／会话／实际服务器 tick 级累计预算。单包大小、64 条注册保护或单次寻路有界，都不能替代累计负载限制。

过时预览可取消、合并或延后；已接受行动不能静默丢失。超预算返回明确状态与可恢复路径，不能伪造失败结果使资源或世界状态失真。多会话要有可观察公平性。

异步工作只使用明确冻结的纯值快照；实时 `MinecraftCellProbe` 与实体／世界查询留在允许线程。缓存依赖来源、目标、体型、区域及必要世界变化证据；命中缓存不等于执行许可仍有效。

物品编码／哈希在必要采样点复用，多个渲染消费者读取同一周期的快照；执行边界仍严格复验。不得用移除校验作为“性能优化”。

日志应关联 operation、actor、来源绑定、阶段、原因码、成本提交、效果确定性、释放与恢复结果。记录注册冲突与未支持维度；限制体积、敏感数据与高基数指标。诊断失败不能改变已确认结果，`-debug` 不能改变授权或行为。

## 15. 分阶段实施与交付门槛

以下是工作包与依赖，不是已完成状态。实际进度和缺口关闭只更新 02；每个阶段可以分多次提交，但不得把未实现阶段描述为整体框架已完成。

### P0：基线盘点与特征测试

阅读真实 AGENTS、01–04、相关版本文档与代码，记录当前依赖、协议／schema、生产入口、租约所有者及支持范围。保留用户改动和现有测试隔离。

先记录玩家近战、Mob 移动／攻击、放置、破坏、持续使用、免费方块交互及 EXIT 的现状测试；旧报告只作为复现线索，不照抄“通过”。建立本轮命令／日志记录。

**退出门槛：**能说明每类行为从输入到最终世界入口、费用、结果和释放的调用链；所有后续改变均有明确基线。未能运行的环境如实记录，但不能因此虚构测试通过。

### P1：先稳定安全和语义边界

先实现并测试纯发现与显式选择的分离、稳定错误码／重试建议、执行效果／费用／release 分量，以及实时 EXIT 豁免与历史回执的独立职责。为受影响值定义迁移边界。

可以先在现有 Player 路径内完成，不等待全部 actor 抽象。保留唯一账本、费用提交点与正常入口；完成／取消／异常使用一致聚合规则。

**退出门槛：**查询不改世界；正常完成后释放异常不抹去效果；迟到查询可取消；旧 ID 不重复执行；历史归档不改变当前豁免。对应 G37–G40 的本次覆盖必须有可复验测试。

### P2：最小能力模型与玩家／Mob 共同纵切

实现最小纯值合同、定义注册与冻结、actor 解析、ItemSource／IntrinsicSource 绑定和统一提交入口。首先迁移现有玩家武器近战及 Zombie 攻击，同时接入各自移动驱动。

在同阶段加入独立测试 Mob 的无物品天生攻击，证明来源不是针对 Zombie 写死的新分支。首次只覆盖已确认的普通动作与伤害规则，不创建新技能体系。

**退出门槛：**玩家、Zombie 和测试 Mob 使用同一根计划、规则授权、费用与结果后端；没有 FakePlayer／伪造 ItemReference；来源变化明确失效；全部世界效果仍经受限驱动。只完成注册与示例类不算通过。

### P3：迁移既有行为与 AI 策略职责

迁移现有移动、放置、破坏、物品使用、方块自身交互、有限远程及规则行动。保存其支持范围与收费语义，移除旧公开旁路；玩家 UI 全部从来源绑定的能力选项提交。

从核心服务中提取 Zombie 策略和非敌对地面移动策略，定义决策视图、结果反馈及回合继续判断。分离目标受击适配，验证第二种受击实体不依赖物种组合表。

**退出门槛：**现有生产能力未回退，空闲／查询／菜单／运行／取消链路正常；AI 提案无世界副作用；一次行动完成后可按剩余资源继续决策。新增生物无需修改核心调度／通用 Mixin。

### P4：效果、时间、恢复与规模收束

完善本次已迁移能力的类型化观察、来源自身变化、延迟效果、时钟与中断合同。迁移受影响 wire／snapshot／envelope，完成能力版本缺失、来源变化、实例切换和合并的恢复对账。

### P5：表现注册、交互与独立兼容验收

040106 检查映射：床朝向/写集合检查接 `TacticalPlanGameTests.interactions`；相同天然来源不同效果合同接 `AbilityPolicyChecks`；当前格式拒绝保护接 `PersistencePolicyChecks`。这些是独立源集里的增量检查，不替代 CAP-T10/19 的 Mob 正常轮转闭环、跨重启或真实显示验收；实际执行状态只在 02 及验证记录维护。

## 17. 完成定义与交付格式

### 17.1 框架完成的必要条件

只有同时满足以下条件，才能在相关文档声明本次能力框架与架构重构完成：

1. 能力定义、来源绑定、当前可用性、调用、许可和运行结果具有明确职责；玩家与 Mob 共用规范提交及计划后端。
2. 既有玩家行为和 Zombie／已批准非敌对移动已迁移；没有运行中的旧旁路、重复资源账户或竞争身体驱动。
3. 物品、天生与测试状态来源能按各自证据失效；source／actor／target 不被绑定为新的固定物种分类。
4. AI 策略不执行世界副作用，执行器不替策略换目标或强制结束回合；感知、关系、目标适配和具体能力分开。
5. 费用提交、效果观察、取消和 release 在正常／异常／死亡／恢复路径均有一致合同；未知效果不重放。
6. 受影响协议、注册版本、来源、保存与合并已有明确迁移或拒绝策略，实时授权不由历史回执隐式决定。
7. 表现通过通道适配消费事实和事件，不改变模拟；独立 compat 模块不修改核心就能实现差异明确的能力／表现闭环。
8. 本次声明覆盖的验收有实际证据，尚未运行或未支持的范围在 02 和最终报告明确保留。

这不是“兼容所有 Mob”的声明。新增实际第三方模组仍需审计其目标、执行入口、副作用、时间及动画合同；框架完成意味着有稳定接入方式，而不是审计工作消失。

### 17.2 明确不算完成的情况

仅新增 interface／record；将 `ServerPlayer` 全部替换成 `LivingEntity`；扩大 `instanceof` 白名单；给怪物创建 FakePlayer 或假物品槽；建立独立 Mob 技能后端；通用管理器仍有每物种分支；兼容测试修改了核心；测试只调用内部方法；只编译未运行；清空存档或关掉主入口后“全部通过”。

### 17.3 每阶段交付内容

交付实际工作树代码与测试，并报告：本阶段改了哪些职责及状态所有权；哪些生产入口已切换；规则与支持范围是否保持；协议／schema／注册版本如何迁移；实际执行命令、环境、日志和结果；未执行与剩余限制。

建议将每阶段证据存为 `docs/reviews/<实际日期>-capability-framework-<阶段>-validation.md`，但进度状态仍只维护在 02。01 只记录有源码与证据支撑的事实；04 记录最终采纳的接口理由；本文件的 CAP-T 标识可被测试和报告引用，不在多个文件分别打勾宣布完成。
