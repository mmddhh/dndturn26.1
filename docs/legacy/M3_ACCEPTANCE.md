# DNDTurn M3 验收与功能缺口

当前阶段：**M3 acceptance**（2026-09-24，按用户指定）。这是唯一的功能缺口与待验收清单；不记录已完成事项、旧 ZIP 评审结论或历史测试通过次数。关闭条目时删除对应缺口，保留仍有效的规则与接入契约。

本清单依据当前工作区源码（含未提交修改）维护，目标为 `neoforge-26.1`，固定 NeoForge `26.1.2.84`。源码可定位的问题与仍需取得的运行证据分别列出，不能互相替代。

规则见 [游戏规则](DECISIONS_RULES_CHECKLIST.md)，理由见 [架构决策](COMBAT_ARCHITECTURE_DECISIONS.md)，固定方法与取消语义见 [接入契约](version-differences/neoforge-26.1.2.84-seams.md)。下文 `core` 指 `common/src/main/java/cc/sighs/dndturn/combat/`，`target` 指 `targets/neoforge-26.1/src/main/java/cc/sighs/dndturn/`。

## 5. 验收顺序与退出条件

1. 先处理环境 ownership、时钟、保存和调度的 E01/E02 未覆盖路径，再处理操作/回合/生命周期及仍开放的 M3-03～M3-06；保持修复范围可验收，不附带无关 target 重写。
2. 随后验证客户端意图闭环与 A01～A08；记录实际版本、命令/场景、结果和未覆盖范围。方法或 test_instance 存在不等于本轮通过。
3. M4/M5/M6 按上表继续接入。`prototypeEnabled` 默认关闭的单玩家/Zombie 原型不改变正式入口门槛；原型只承诺正常退出/卸载/停止时交还内存 held ticks，不承诺崩溃恢复。
4. 代码修改后，在 `targets/neoforge-26.1/` 使用 JDK 25 执行 `gradlew.bat clean build`、`gradlew.bat :common:test`、`gradlew.bat runGameTestServer`，并进行真实客户端 + dedicated server 验收。common 受影响时按 [维护矩阵](MAINTENANCE_WORKFLOW.md) 构建其他 target。
5. 正式入口须在承诺范围的服务端执行、跨域/生命周期、恢复和客户端验收后开放；文档清理不改变该门槛。
