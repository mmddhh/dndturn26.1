## 一、上层 DnD 定义是否已经明确

### 1.1 审查结论

**基本职责已经明确，生产主链可以继续使用；但“上层完全封闭、下层只填数字”的状态尚未成立。**当前还存在几个会迫使翻译层绕过上层的接口限制，应作最小修补，再增加 Mob 适配。

本版相较 `074734` 仅改变 `ClientTacticalPlan.java`、`TacticalOverlay.java`、`tactical.css`、`tactical.html` 四个文件，没有修改 common／服务端能力合同。不能把 UI 更新推断成新的原生能力翻译功能。当前归档包含232行更正版 AGENTS、未包含 docs；另行呈现的旧158行AGENTS不是本归档的当前文件。[E01](reviews/20260927-133552-mob-translation-evidence.md#e01)

| 维度 | 当前代码的明确部分 | 尚需收束的部分 | 本轮判断 |
|---|---|---|---|
| 规则权威 | `CombatEngine` 管成员、阶段、资源、操作及终态 | 不把原版属性或AI状态变成第二份规则余额 | 保留 |
| 能力定义 | `TacticalBehavior` 的 ID、版本、目标集合、来源验证、开始／tick／取消／释放 | 类同时暴露元数据与执行钩子；`cost()`仍返回综合分类枚举 | 定义存在，不必强行新建同名 `AbilityDefinition` |
| 来源 | `AbilitySource` 区分装备、基础、天生、状态授予及 grant | 装备读取／采样仍依赖玩家库存；一项行为每次 source 查询只能返回单个绑定 | 值语义基本明确，平台端口不充分 |
| 调用与许可 | `TacticalIntent`、统一 submit/PLAN、子效果许可、来源和实例复验 | 攻击被硬限ENTITY；缺能力自有的有界参数合同 | 修接口，不取消校验 |
| 费用与结果 | 普通动作与移动分开；效果和释放证据分开；未知不重放 | 分类、目标形状、费用和Operation Kind仍由同一枚举推导 | 规则可保留，表达需要拆开 |
| AI | 注册策略、只读 `DecisionView`、结果反馈、提出后交共同后端 | 成员＋视线枚举不等于原生感知；来源发现与玩家菜单不同 | 不是要重做策略，而是补其事实来源 |
| 平台执行 | 玩家输入与Mob导航分别驱动，共用计划 | Mob设备、特殊移动、完整攻击语义和公开状态端口不足 | 下阶段重点 |
| 扩展证明 | 测试已有正常轮转的天生攻击→后续移动路径 | 测试仍在核心Java包，使用包内 `IntrinsicMelee`、`attackPlan` 等 | 不等同真正独立compat API验收 |

<a id="policy-boundary"></a>
## 二、先固定“谁决定什么”，防止翻译层暗改规则

### 2.1 当前 DnD 政策与原生事实不同

当前 `CombatRules` 明确实现 d20＋5、自然1/20、优势／劣势、护甲及盾牌AC、韧性扣减和暴击。普通近战仍使用一格几何＋可见性；远程规则常量为6。它们不是“忘记从Mob属性读出来”的同一种错误。[E03](reviews/20260927-133552-mob-translation-evidence.md#e03)

当前已审查规则还区分：玩家武器行为读取武器贡献，Zombie适配读取实体攻击属性；空手是另有来源和效果政策的自身能力。把所有分支改成 `getAttributeValue(ATTACK_DAMAGE)` 可能改变玩家数值及空手装备处理，不能称为无行为变化的重构。

| 项目 | 事实来源 | 最终决定者 |
|---|---|---|
| 原生属性基值、有效值、当前装备／姿态 | 原版运行时和已审计mod端口 | 只读事实层，不自行裁定行动 |
| 动作/反应/移动费用、命中、暴击、伤害折算 | 已确认DnD规则与能力映射政策 | 现有规则层 |
| 原生攻击几何、目标部位、可用执行入口 | 该行为/实体实际方法及组件 | 适配器提供事实/条件，上层选择经批准的范围政策 |
| 感知、仇恨与技能阶段 | 经过审计的Goal/Brain/实体状态 | 感知/策略映射；同场不自动敌对 |
| 导航、碰撞、位移、实际受伤及生命维护 | 原版获准执行链 | 平台驱动，受有限许可约束 |
| 延迟引信、周期效果、自动过程 | 过程状态及局部有效时钟 | 环境/执行阶段调度，不消费思考时间 |

### 2.2 范围政策不能偷换

翻译层应能提供 `NativeReachEvidence`；但此证据不自动成为所有战术能力的最终判定。

- 既有普通近战保留当前DnD范围，直到有明确规则修订。
- 新的、经批准使用原生范围的能力可采用对应原生几何政策，并记录所用政策版本。
- 不把DnD范围与原生范围默默取交集；那也会改变现有行为。
- 不临时把实体移动到候选点调用范围函数，再移回。规划用捕获体型和几何的纯值计算；最终执行在当前真实状态重新检查。
- 无法在假设位置重建某mod的特殊范围逻辑时，可有界搜索/最终拒绝或要求提供者补齐；不能返回虚假精确预览。

本次没有批准所有武器/生物统一改用原版近战距离，也没有新增范围攻击、PvP或飞行费用。原版判定优先复用，含义是少复制可复用实现，不是原版规则自动压过已定DnD政策。

### 2.3 特殊技能存在上层未定政策时

Creeper自爆、Guardian复合伤害、瞬移和周期光环可以先完成识别、事实采样、阶段驱动测试与效果观察。若尚未明确其动作消耗、命中次数、解除条件或多个原生伤害片段如何折算，标记 `RULE_MAPPING_REQUIRED`，不自行给它免费或额外动作，也不阻断其他已明确定义的翻译工作。

“原生能运行”与“已获准在DnD里以某种规则运行”是两种证据。

<a id="layers"></a>
## 三、MOB翻译层的职责和边界

### 3.1 整体路径

```text
原版／mod 实体、属性、装备、导航、已审计Goal/Brain/特殊过程
                 ↓ 读取与识别（不执行世界动作）
NativeMobFacts + BehaviorCandidate + CompatibilityEvidence
                 ↓ 已注册的翻译政策
能力来源绑定 + 目标/范围合同 + DnD数值输入 + 阶段/效果描述
                 ↓
已有TacticalCapabilities / DecisionView / TacticalIntent
                 ↓
已有规则验证 → PLAN → 受限NativeExecutionPort
                 ↓
原版效果观察 → 原有费用/结果/恢复证据 → 表现事实与事件
```

翻译是**显式语义映射**，不是反射调用任意方法、运行AI后猜它想做什么、或自动反编译未知Java为技能。方法名、继承关系、装备外观和属性存在只能提供线索，不单独授予能力。

### 3.2 五项责任，而非必须五个管理器

| 职责示例 | 输入与输出 | 所有权边界 |
|---|---|---|
| `NativeFactsReader` | 活实体→属性/装备/体型/运行模式值及采样证据 | 主线程读取；不持有长期世界对象到common/网络 |
| `NativeBehaviorInspector` | 显式注册、已知组件/Goal家族→候选与未识别项 | 不调用canUse/start/tick求答案 |
| `MobAbilityTranslator` | 候选＋规则映射→已有能力定义/绑定/条件 | 不扣费、不复制规则引擎 |
| `NativeExecutionPort` | 有限许可＋阶段上下文→获准执行及观察 | 只暴露审计动作，不给任意Mob.tick权限 |
| `CompatibilityResolver` | 匹配证据、优先级、依赖→支持矩阵与原因 | 区分检测到、已审计、缺少规则、缺少驱动、运行失败 |

可以合并合理职责或复用当前类；目标是依赖方向和状态生命周期真实分开。未定义能力产生可诊断的候选，不把候选直接放进“可执行能力”集合。

### 3.3 能力面与分类标签正交

Ground/Air/Swim/Climb是移动能力，Pathfinder是实现线索，Beast/Humanoid是形态描述，Player/AI是控制来源。它们不能串成一棵“高级类人生物”继承树。模型是人形不证明有手持武器执行端口；`PathfinderMob`不是DnDTurn所有路径能力的永久准入条件。

属性、装备、移动、感知、动作驱动、效果接收、表现分别报告支持。环境参与者不是Mob，不需要身体或物品端口，不占真实实体成员名额。

<a id="facts"></a>
## 四、原生数值与装备：建立事实层，而非再建物种数值表

### 4.1 数据读取优先级

1. 活实体当前属性/组件及声明过的运行端口。
2. 对应行为的已审计原版方法/数据（例如有效范围、攻击持续时间）。
3. 显式兼容提供者返回的有版本语义数据。
4. 类型默认值只用于来源解释/诊断，不替代当前实体状态。
5. 无可靠读取方式时返回缺失/不支持，不猜默认数值，也不为了查询给实体添加属性。

`.109`明确提供 `getAttributeBaseValue` 与 `getAttributeValue`；`AttributeInstance`按加值、基数比例、总量比例和sanitize得到当前有效值。默认 `createAttributes()` 不是运行时真相。[S01](reviews/20260927-133552-mob-translation-evidence.md#s01)

### 4.2 每个事实要有语义及来源

推荐返回有限的 `NativeStatsSnapshot`，至少区分：

```text
actor/instance + observation stamp
attribute key + presence
current base value + current effective value
optional bounded modifier evidence
sampling phase / equipment evidence
consumer meaning and units
```

缺失属性与数值0不同；字段缺失不得默认等于Zombie攻击力。先用属性存在性检测或已声明端口，再读取。属性ID、值、modifier ID/operation可记录；不知道modifier来自哪个外部系统时标记未知，不靠名字猜装备/药水来源。

| 事实 | 建议读取 | 不能由它推出什么 |
|---|---|---|
| 移动属性 | `MOVEMENT_SPEED`当前有效值，另记录驱动/目标速度倍率 | 不是每tick格数，不是剩余移动费 |
| 标准索敌尺度 | `FOLLOW_RANGE`存在时的有效值 | 不等于所有Brain/技能的唯一视觉半径或敌对关系 |
| 原生近战属性输入 | `ATTACK_DAMAGE`当前有效值 | 不等于附魔/目标类型/物品回调后的完整攻击效果 |
| 属性基值 | `getAttributeBaseValue` | 不等于排除了装备影响的“本次天生能力伤害”政策 |
| 击退/抗击退 | 对应有效属性及本能力政策 | 有属性不代表这次能力允许推开，也不直接等于最终位移 |
| 护甲/韧性 | 对应当前有效值 | 不允许再重复应用已被DnD替代的减伤 |
| 原生可变能力参数 | 已审计getter/组件/provider | 不与策略私有常量或全局默认混为一份真相 |

### 4.3 避免伤害双计与术语混乱

至少分别命名：`nativeBaseValue`、`nativeEffectiveAttribute`、`sourceSpecificInput`、`mappedDndInput`、`observedDamage`。当前 `MeleeEffects.baseDamage`实际上是交给DnD折算的输入，不总是Minecraft Attribute base，文档及诊断必须注明。[E03]

`.109 Mob.doHurtTarget`读取有效ATTACK_DAMAGE，随后执行附魔、物品目标相关增伤、hurt、击退、物品命中钩子与post-attack效果。因此：

- 已使用有效属性时，不再把同一装备/状态modifier加一次。
- 原生攻击属性不是最终目标相关伤害；不能把 `getAttributeValue` 输出标为“完整原版伤害”。
- 玩家武器贡献与Mob有效攻击属性当前是不同DnD输入政策，先保留并命名，不能为了统一简单合并。
- 玩家空手是独立自身能力。持有武器/工具但显式选择空手时，不通过临时脱装备或简单 `effective - weaponBonus` 猜数值；乘法修正和能力专属政策使这种减法不可靠。
- 额外效果（例如Zombie点燃）要独立授权与观察；不能把它折成一个额外固定伤害后宣称语义相同。

固定源码依据见[S01](reviews/20260927-133552-mob-translation-evidence.md#s01)、[S04](reviews/20260927-133552-mob-translation-evidence.md#s04)。

### 4.4 装备同步与采样时机

`.109 LivingEntity.collectEquipmentChanges()`把装备modifier更新到AttributeInstance，还执行装备事件与位置相关附魔效果。不能为让属性“刷新一下”而在查询里额外调用整个装备检测链。[S01]

定义经确认的装备修订和属性采样阶段。刚切槽/损坏/状态变化时，若装备事实与属性尚不一致，等待正确的原版更新点、拒绝旧快照或使用经审计的纯计算视图；不返回把新物品和旧有效属性混合的值。

默认提交及效果前复验；弹射物按已定发射时来源捕获，不能命中时读取射手新装备。持续能力自己的耐久/弹药变化有来源地更新预期证据，不使自己误取消，也不接受任何外部换物。不在整个遭遇中永久缓存同一数值，不在每个渲染消费者重复序列化属性和ItemStack。

<a id="discovery"></a>
## 五、如何可靠识别原生行为

### 5.1 证据分级

| 证据 | 能做的事 | 不能做的事 |
|---|---|---|
| 显式兼容注册/原mod提供者 | 绑定版本、支持的入口、读取依赖、效果/时间合同 | 仍须通过DnD关系、资源、目标与域验证 |
| 已审计原版行为家族和确切配置 | 复用标准原型；声明哪些方法/组件在该版本已检查 | 不能推断所有子类或全局注入都不改变行为 |
| Goal/Brain/导航/属性结构特征 | 产生能力候选、确定可探测端口 | 不是纯意图，也不是执行许可 |
| 名字、Monster标签、模型或武器外观 | 诊断展示和人工辅助 | 不自动授予近战/敌意/远程/施法 |

相同注册定义可以应用多个actor，actor可拥有多个不同绑定。返回来源集合，而不是把同名能力的两个独立grant静默合并；初次可以只实现实际需要的来源枚举，但接口不要固化“一行为每hand唯一来源”。

### 5.2 禁止以执行代替发现

`.109 MeleeAttackGoal.canUse()`会更新时间戳并建立路径；start启动导航，tick消费随机数、刷新路径和冷却并可能攻击。TargetGoal的继续判断也可能写target和未见计数。Brain.tick同样会推进记忆和行为。[S03](reviews/20260927-133552-mob-translation-evidence.md#s03)

不得在预览/AI评分中调用这些方法后说“没有攻击就算纯查询”。可读取已审计的值、缓存和组件；其中只影响性能的观察缓存也要有明确边界。未知Goal不通过反射试跑，不克隆一个假实体执行来推导真实世界结果。

### 5.3 一个实体多种行为，不把物种等同单技能

`.109 Zombie`除了ZombieAttackGoal还注册了更高优先级的SpearUseGoal；Enderman注册近战之外还有注视、目标、瞬移相关及搬方块逻辑。`extends Zombie`只能说明某些结构可复用，不能证明它只会标准挥击或已经完整兼容。[S04]

建立按行为的支持记录：普通近战已映射、长矛行为未映射、点燃已审计/缺规则、特殊目标策略待适配。已明确允许的降级要显示；没有批准时不能把未知特殊攻击静默替换成普通近战并宣传完整还原。

<a id="geometry"></a>
## 六、移动、攻击几何与感知接口

### 6.1 移动端口

读取当前导航类型、移动控制器、必要体型/姿态/载具状态以及相关属性。标准地面导航可复用已审计驱动；飞行、游泳、爬行等按实际端口匹配，不按外观分类自动执行。

规划/执行仍走原版控制、travel、collision；`MOVEMENT_SPEED`与navigation speedModifier只是输入，实际主动移动按已有观察规则收费。不能使用 `speed × ticks`直接传送或预扣等价格数；也不能因不会移动就停止生命维护或外力。

标准Profile可提供候选驱动，但必须审计特定实体的控制器及外层tick。未知驱动显式不支持该移动维度，保持普通身体运行；不要冻结整只Mob来隐藏能力缺口。

### 6.2 执行位置与原生范围

`.109 Mob.isWithinMeleeAttackRange()`读取active item的ATTACK_RANGE，没有时使用默认reach，并结合攻击者/载具包围盒与目标hitbox、最小和最大范围。攻击取武器时另使用getWeaponItem，两者并非无条件“主手同一件物品”。视线还在攻击Goal中单独判断。[S02](reviews/20260927-133552-mob-translation-evidence.md#s02)

因此范围接口应表达：原生几何证据、当前姿态/装备依赖、目标部位/根身份、最小/最大作用区、视线要求，以及实际采用的DnD范围政策。规划和执行使用同一政策及可复验依赖，不能预览原生范围、执行又偷偷用一格，反之亦然。

模板范围计算只覆盖已审计的原版方法语义；特殊override需提供自己的纯候选点判定或承认预览不精确。不要反复setPos试判定，也不要把`FOLLOW_RANGE`拿来当武器射程。

### 6.3 感知、关系与承诺

标准TargetGoal读取FOLLOW_RANGE，但还包含目标类别、队伍、攻击合法性、视线、未见记忆、可达性等条件。Brain Sensor和事件仇恨另有范围与期限；原始方法是否纯读需逐个核验。[S03]

翻译层提供已知对象和关系证据，策略决定偏好，上层校验最终许可。不得把会话全成员当作全知可见目标，也不能把本次getTarget当作全部敌对关系。禁止PvP继续保留；已经允许的非敌对漫步不授予攻击或工作。

某些行为在确认目标时会修改原生状态。例如Enderman.setTarget会改变追击速度modifier。[S04] 只读决策视图不得为此调用setTarget；在行动目标正式承诺的授权步骤调用审计过的状态桥，并相应重新采样属性。避免既宣称保留原生加速，又永不推进它的触发状态。

<a id="archetypes"></a>
## 七、以行为原型复用，不为每个Mob再建系统

下表是翻译目标与必要边界，不是本版已支持清单。原生时间/数值可读不代表其DnD规则已经批准。

| 原型 | 参考行为与事实 | 翻译出的上层结构 | 必须专门处理的差异 |
|---|---|---|---|
| `StandardMelee` | ZombieAttackGoal继承MeleeAttackGoal；Enderman直接使用后者；调用汇聚到doHurtTarget | 目标承诺→接近→一次合法攻击→受控效果与终态 | 目标关系、范围政策、武器输入、点燃/附魔、特殊防御/瞬移 |
| `EquipmentRanged` | 明确持械/弹药与受审计射击驱动 | 装备绑定→瞄准/使用阶段→发射证据→延迟命中 | 不要求玩家库存；消耗与发射源锁定；未审计弹药拒绝 |
| `ChargedTargetAttack` | GuardianAttackGoal持有attackTime、视线与beam target，最后两条伤害调用 | 锁定→获准进度→表现事实→有限复合效果 | 两段如何对应DnD命中/伤害须明确；不能天然扣两动作或强制合成一种伤害 |
| `ArmedSelfDestruct` | Creeper膨胀方向与tick中的引信推进、爆炸、云和移除 | 主动触发/解除＋持续过程＋爆炸效果组合 | 触发与持续进度分别调度；爆炸伤害/位移/改块/云/死亡各有证据 |
| `PeriodicAura` | ElderGuardian.customServerAiStep按周期给附近玩家挖掘疲劳 | 来源实体＋周期条件＋有界目标集合＋状态效果 | 不是普通Guardian能力，也不是每tick一次主动攻击；思考时间不能推进周期 |
| `Reposition` | Enderman等明确的传送行为 | 原因/落点条件→授权位移→观察 | 主动传送与受击触发反应不能全归免费移动；不能借传送替代普通路径 |

原版细节依据[S04](reviews/20260927-133552-mob-translation-evidence.md#s04)、[S05](reviews/20260927-133552-mob-translation-evidence.md#s05)。

### 7.1 标准近战的复用边界

Zombie和Enderman可以共享标准近战执行家族，不意味着它们共享完整策略。Zombie在super.doHurtTarget成功后有条件点燃；Enderman的注视/敌对与其他行为位于别处。识别到MeleeAttackGoal不能省略攻击者方法、物品回调及受害者动态hurt入口的审计。

可采用两类经过证明的桥接：

- **翻译输入＋分解效果驱动**：现有DnD独占命中/数值折算，复用受伤与受控额外效果入口，逐项防重复。
- **审计过的原生阶段调用**：仅当能够在首个副作用前约束原生伤害/附魔/资源/生成分支，并证明不重复计算时，执行对应阶段。

选择哪类取决于具体行为和target版本。不得先完整调用doHurtTarget，再额外应用DnD伤害；也不得仅替换最终血量就声称保留所有原版钩子。每种额外效果明确触发条件是“攻击尝试成立”“命中”“原生hurt接受”还是“实际生命损失”，不能混用。

### 7.2 主动技能、反应与周期过程不能都塞进一份Action

控制类型由触发原因、阶段和时间合同决定，不由方法位于`tick`还是`Goal`决定。

- 主动选择的攻击/点火/施法由actor获准行动启动。
- 已启动技能的蓄力采用其明确执行进度；已委托的引信/持续危险由环境有效步推进。
- 被动受力/伤害/生命周期按已定默认世界规则处理，不因此获得新的主动技能权。
- 周期光环是有来源的环境过程，不需要伪造玩家物品或每个目标一个主动行动。
- 某行为究竟应占动作、反应还是环境过程，若没有规则依据，先保持可检测但不可正式启用，不猜免费。

环境是常驻类型级末位参与者，原生过程关联来源实体但不会给每个过程新增先攻席位。不要为每个同步方块响应附加原始玩家因果授权；显式能力/延迟效果的来源记录与被否定的全局因果追踪是两件事。

### 7.3 周期有效时间要保留相位

`.109 ElderGuardian`使用 `(tickCount + entityId) % 1200`，并施加有期限的效果；只在环境步骤偶尔调用这个函数，不能证明周期已正确映射。真实tickCount继续增长时可能跳过触发或被等待影响。[S05]

为受托管过程捕获剩余时间/相位、最近有效步骤和归属；用实际获准步推进，不把全局tickCount改掉。入域、离域、合并、卸载/恢复时不得重置周期白送一次触发，也不补跑等待时间。效果本身的期限/周期治疗与发生器的周期分别处理。

Creeper同样不能恢复完整tick来“推进一次引信”，其调用混合了演出、膨胀、爆炸和super.tick；仅门控isAlive分支表示阻止了行为，不等于已经构造了可用技能。

<a id="execution-api"></a>
## 八、提供真正可由独立兼容模块使用的接口

### 8.1 有限公开端口

当前测试位于 `cc.sighs.dndturn.combat`，能访问包内 `IntrinsicMelee`、`TacticalActions.service`、`attackPlan` 和 `finish`；这不证明另一包/模组可以只用公开API复用它们。[E06]

应提供以下语义端口，名字不固定：

| 端口 | 公开给适配器的能力 | 不公开的能力 |
|---|---|---|
| 只读执行上下文 | 规范调用、绑定、捕获事实、当前阶段/进度和许可摘要 | 任意修改成员/余额/版本 |
| 装备与属性视图 | actor所属装备地址、已确认快照、必要修饰和可用端口 | 伪造玩家背包、任意属性注入 |
| 获准近战/远程/状态执行 | 执行本次许可覆盖的动作、报告有限效果 | 整个service、engine、无限制Level写入口 |
| 运行状态托管 | 每计划实例的私有状态、推进、取消、release与值化证据 | 单例适配器自建无人清理的全局运行Map |
| 结果/演出提交 | 带operation/步骤/效果序号的观察和演出事实 | 重写历史终态或由动画决定伤害 |

调用许可同时约束实体实例、能力/翻译版本、阶段、效果类别、目标与次数；“当前存在PLAN”不意味着任意回调都获准。嵌套效果沿已有受限父子机制，不因进入一次ThreadLocal就放行未知的所有hurt、生成和改块。

### 8.2 运行状态与持久证据

适配器的状态由计划实例创建/推进/释放，普通完成、取消、实体退役和异常均有幂等路径。跨tick保存剩余进度、来源依赖和效果证据，不持久化原始Goal/Brain对象或lambda。

状态有两个层次：短期平台对象只属于target的当前实例；可恢复值只有明确版本/codec和有界字段。能够保存状态不表示可以重新start已发生的攻击。来源失效、provider缺失、当前版本不再支持时给出可审计结局；世界效果未知不重放。

### 8.3 翻译策略身份与效果账本

一次调用及其结果至少可追溯：能力ID/版本、来源绑定、翻译提供者/映射政策ID和版本、必要原生快照、作用范围、执行/环境步骤、效果确定性及release结果。原始请求ID保持不可变；执行中的合法消耗形成后续证据，不换负载借旧ID再次执行。

对状态、生成或多目标能力，扩展有界观察合同，而非只增加枚举。当前默认Sample只采actor/主目标的位置、生命、吸收和部分物品/方块，不足以证明周期光环或爆炸全效果；未知分量明确标识，不能空列表代表“一切未发生”。

<a id="compatibility"></a>
## 九、自动兼容策略：按证据和能力维度接入

### 9.1 自动化程度与支持维度分开

自动化来源可标记为：显式provider、审计过的原版家族、结构候选、未识别。支持则分别报告：participant、body、movement、perception、target receiver、ability、strategy、presentation、recovery。它们不是线性升级等级；一个没有自主AI的实体也可以成为合法受击目标。

| 对象情况 | 可以自动完成的部分 | 仍须证明的部分 |
|---|---|---|
| 普通Mob、有原版属性 | 在原有规则允许范围内采样身份/属性/身体事实 | 不是自动授予攻击或完整先攻策略 |
| 已审计地面导航合同 | 地面移动端口及对应范围内的fallback | 不授权繁殖/工作/custom AI；特殊控制器不能只凭基类放行 |
| 匹配已审计标准近战provider | 绑定普通近战家族、数值源和既定策略 | 关系、物品、特殊攻击钩子、接收侧和版本仍复验 |
| 实体子类重写攻击/导航，或相关mod改变入口 | 保留已经证明不受影响的维度 | 冲突行为降为候选/需显式适配，不默认继承完整语义 |
| 特殊Boss、非标准动画或多部件 | 共用已有授权/账本和支持的端口 | 只为缺失的阶段、效果、移动/部位和表现补适配，不建Boss引擎 |

Body或Humanoid标签不决定手/装备权限。不会因没有动画适配就拒绝服务器合法攻击，也不因动画正常就声称保留特殊技能。

### 9.2 内置fallback与外部覆盖

当前Zombie attacker是`instanceof Zombie`，receiver却精确匹配EntityType.ZOMBIE；普通子类可能可攻击但不可被当前桥接攻击。新增专用attacker还会触发歧义。[E03]

修复应给内置fallback与显式覆盖建立确定的优先级/替换声明，保持歧义失败关闭，不靠注册顺序。不要求把receiver扩大为所有LivingEntity；按实际受伤语义、上下文和override审计扩展。

Goal或方法继承关系只是证据之一。静态签名相同、没有直接override，不足以证明其他Mixin/事件没有改变语义；因此“自动”必须带已审计版本/依赖范围，而不能承诺识别任意未知mod的全部副作用。

## 十、时间、发现预算、缓存与恢复

### 10.1 采样与发现预算

以actor实例、装备/状态修订、translation版本和必要世界依赖构建有界快照。先枚举来源绑定，再按目标需求评估；不要为每个成员重新扫描全部注册项。

当前一次AI捕获在成员数和每个目标×能力循环中扣候选预算，超预算发生在快照返回前，下一tick从头开始。多能力扩展前必须提供可恢复游标/分批计算及公平性；仅调大常量不能证明最终可完成。[E05]

来源变化只使相关进度失效；过时预览可以丢弃，已接受行动及费用不可以静默丢弃。不在异步线程读取活Level/Entity；异步纯值结果返回时仍复验，不靠缓存代替授权。

### 10.2 时钟与绑定切换

能力执行、环境周期、AI记忆、世界日程和显示使用不同语义时间。源实体结束回合、死亡或换装备，不自动删除已经发射的效果来源；效果也不能借来源尚在就任意推进。

合并、入/离域、重连、实体实例替换及资源/适配重载，明确哪些时间与状态继续、停止或核对。依赖loader版本和已解析provider版本；正在执行时不能用同名新实现接管旧阶段。

保留当前UNKNOWN与安全隔离合同。归档/旧存档兼容是既有独立政策，本文件不新增“全部迁移”或“全部删除”的决定；只要求新增翻译字段具有显式版本、拒绝/迁移与恢复证据。当前版本更新计数不等于平台恢复已验证。

### 10.3 诊断

每个翻译结果能解释：识别到了什么原生行为、依据哪个provider、采用哪个DnD政策、缺哪个端口/规则、范围或来源为何失效、预算为何延期。显示文本与机器错误码分开，不用日志文案做重试判断。

有界记录数值来源链与效果序号即可；不要每帧序列化整个Brain/ItemStack/世界或无限保留高基数指标。诊断不开权限，不让 `-debug` 改变能力支持范围。

### 12.1 同一行为的对照测试如何判断

不能要求“原版总伤害等于DnD总伤害”来证明翻译正确：命中、AC和韧性已经是上层规则。应分别比较：原生事实采样正确、采用的政策正确、原本声明保留的副作用触发条件正确、DnD资源和结果只提交一次。

随机行为要明确受哪条已定时钟/随机源驱动，捕获必要种子或输入；查询不得改变未来命中或原生技能随机结果。不通过修改生产先攻或删断言固定测试；夹具可布置位置，但不得以传送替代待测移动。
